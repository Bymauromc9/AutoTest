Tema 0

Algoritmos, programas y procesos

¿Qué tareas puede realizar un ordenador? Los conceptos de base: computador, algoritmo, lenguaje, programa, proceso, estado y variable.

0.1Computador y algoritmo

Un computador es un mecanismo digital de propósito general que se convierte en un mecanismo para un uso específico cuando procesa un determinado algoritmo. El mismo hardware sirve para todo: lo que lo especializa en cada momento es el algoritmo que ejecuta.

Un algoritmo es una secuencia de instrucciones (operaciones) que especifican las acciones que debe ejecutar un computador para realizar una tarea.

Área de un triángulo rectángulo (en lenguaje natural)

INICIO
  Obtener las medidas de la base (b) y la altura (h)
  Multiplicar base por altura (b × h)
  Dividir entre 2 el resultado (b × h) / 2
FIN

El mismo estilo en notación algorítmica

Léxico
  a, b, c: Entero;
Algoritmo
  b ← 2;
  a ← 3;
  c ← a + b;
  Escribir (c);
Fin.

La noción de algoritmo es más general que la informática: cualquier receta que resuelve un problema lo es.

0.2Lenguajes de programación y traductores

El computador sólo ejecuta instrucciones máquina, muy simples. Un computador está caracterizado por el conjunto de instrucciones que puede ejecutar. Formato: código + [operandos] (entre 0 y 3). El código indica la operación (suma, resta, comparación, salto…) y los operandos, direcciones de memoria o valores.

Los lenguajes de programación son notaciones que expresan las operaciones que queremos que haga el ordenador con un nivel de abstracción superior al del lenguaje máquina. Por eso hace falta un traductor: compiladores (traducen el programa completo a código máquina antes de ejecutarlo; es lo que hace g++ en prácticas) e intérpretes (traducen y ejecutan instrucción a instrucción).

  • El mismo algoritmo se puede expresar en lenguajes diferentes (C++, C, Python…).
  • En el análisis se usa una notación algorítmica (la de clase, que llamaremos SP) para evitar los detalles del lenguaje y centrarse en el proceso que debe llevar a cabo el computador.
  • Un programa es la expresión de un algoritmo en un lenguaje de programación concreto.

Algoritmo

Léxico
  numero: Entero;
Algoritmo
  Escribir ('Este es el segundo programa');
  Escribir ('Escribe un número');
  Leer (numero);
  Escribir ('La variable numero ha tomado el valor ', numero);
Fin.

Programa (C++)

#include <iostream>
using namespace std;
int main ( ) {
    int numero;
    cout << "Este es el segundo programa" << endl;
    cout << "Escribe un número ";
    cin >> numero;
    cout << "La variable numero ha tomado el valor " << numero << endl;
    return 0;
}

0.3Programa, proceso, estado y variable

  • Proceso: un programa en ejecución. Se caracteriza por una sucesión de estados, desde un estado inicial hasta un estado final.
  • Estado de un proceso: determina su grado de progreso; viene dado por los valores de las variables y un indicador de la siguiente instrucción a ejecutar.
  • Variable: magnitud o información manejada por un algoritmo a la que se da un nombre y que registra un valor. Representa una entidad del mundo real relevante para el problema (la altura, una nota…).

Si ejecutamos el programa anterior cuatro veces con 5, 4, 0 y 1, tenemos un programa y cuatro procesos: el texto es el mismo, pero cada ejecución recorre sus propios estados.

Ojo en el test

Programa ≠ proceso. El programa es estático (texto); el proceso es dinámico (ejecución). Y el estado no son sólo las variables: también cuenta por dónde va la ejecución.

Tema 1

Léxico y organización de un algoritmo

Qué es el léxico de un algoritmo, los tipos primitivos con sus operaciones, las acciones primitivas y las dos primeras formas de organizar las acciones: secuencia y análisis de casos.

1.1Léxico y control de un algoritmo

Un algoritmo = léxico (informaciones + acciones) + control (el orden y las condiciones en que se ejecutan las acciones: secuenciación, análisis de casos e iteración o recursión). Construir un algoritmo es elegir informaciones y acciones y decidir cómo organizarlas en el tiempo para obtener el resultado por acumulación de sus efectos.

Ejemplo, ir al cajero: informaciones: cantidad a reintegrar, cuenta, saldo; acciones: seleccionar cuenta, consultar saldo, reintegrar.

Abstracción: «eliminar detalles innecesarios y considerar lo esencial». Es el mecanismo fundamental para dominar la complejidad; el léxico (variables y acciones) fija el nivel de abstracción.

Elemento del léxicoQué se especifica
Información (variable)nombre y tipo
Acciónnombre, precondición (lo que debe cumplirse antes) y postcondición (lo que se cumple después)
Tipo de datodominio de valores y operaciones posibles sobre ellos

Ejemplo: para retirar (cuenta, cantRet), pre: 0 < cantRet ≤ saldo; post: el nuevo saldo es el anterior menos cantRet.

Estructura de un algoritmo

LÉXICO

  A1 : una acción

    POST { postcondición de A1 }

ALGORITMO

  POST { postcondición del algoritmo }

1.3Acciones primitivas: asignación, Leer y Escribir

La asignación <variable> ← <expresión> es la acción primitiva que caracteriza a los lenguajes imperativos: se evalúa la expresión de la derecha y el resultado se guarda en la variable de la izquierda (el valor anterior se pierde). El nuevo valor puede depender del anterior: longitud ← longitud / 2.

Entrada: Leer (lista de variables) asigna a cada variable el valor introducido por teclado. Salida: Escribir (lista de expresiones) envía al terminal los valores de evaluar cada expresión.

Leer y Escribir

LÉXICO
  nota : Real; nombre : Secuencia de caracteres; numexam : Entero;
ALGORITMO
  Leer (nota, nombre, numexam);      // teclea: 6.0 Ana 200
  Escribir (nota, nombre, numexam)   // pantalla: 6 Ana 200
FIN

1.4Composición secuencial

Para reducir la complejidad se introducen estados intermedios: el problema se descompone en subproblemas más simples que se resuelven de forma independiente. {E0} A1 {E1} A2 {E2} … {En}.

Problema: dado un número de segundos n < 106, expresarlo en días, horas, minutos y segundos. Diseño: n = 86400·d + 3600·h + 60·m + s, con 0 ≤ h ≤ 23 y 0 ≤ m, s ≤ 59.

Segundos → días, horas, minutos y segundos

LÉXICO
  n : Entero [0, 999999];   // dato: nº de segundos
  d : Entero ≥ 0;           // días
  h : Entero [0, 23];       // horas
  m, s : Entero [0, 59];    // minutos y segundos
  rd : Entero [0, 86399];   // resto de días
  rh : Entero [0, 3599];    // resto de horas
ALGORITMO
  Leer (n);
  d ← n DIV 86400;  rd ← n MOD 86400;   { n = 86400·d + rd, 0 ≤ rd ≤ 86399 }
  h ← rd DIV 3600;  rh ← rd MOD 3600;   { rd = 3600·h + rh, 0 ≤ rh ≤ 3599 }
  m ← rh DIV 60;    s ← rh MOD 60;      { n = 86400·d + 3600·h + 60·m + s }
  Escribir (d, h, m, s)
FIN

Ejemplo resuelto

  1. d = 309639 DIV 86400 = 3; rd = 309639 − 259200 = 50439.
  2. h = 50439 DIV 3600 = 14; rh = 50439 − 50400 = 39.
  3. m = 39 DIV 60 = 0; s = 39 MOD 60 = 39.

Resultado309639 s = 3 días, 14 h, 0 min, 39 s

Es la misma estrategia del desglose de billetes de la práctica 2: cociente con el más grande y seguir con el resto.

1.5Análisis de casos

Técnica de descomposición que particiona el dominio en subdominios (casos); cada subproblema es el problema restringido a su subdominio. La partición puede estar guiada por los datos (porcentaje de impuesto según la renta: < 12 000, 12 000–35 000, > 35 000) o por los resultados (sobresaliente [9, 10], notable [7, 9), aprobado [5, 7), suspenso [0, 5)).

Condiciones de corrección

  1. Cubrir todo el dominio inicial.
  2. Que los subdominios no se solapen.

Además, la postcondición de cada caso debe cumplir la del problema.

Errores típicos: olvidar casos e incluir casos repetidos

// DESCOMPOSICIÓN INCORRECTA (edad en [0, 120])
if (edad >= 0 && edad <= 12) {          // Infantil
} else if (edad >= 12 && edad <= 18) {  // Joven: SOLAPAMIENTO en 12
} else if (edad > 20) {                 // Adulto: FALTA COBERTURA de 19 y 20
}

Composiciones de la notación:

SEGÚN

SEGÚN c1, c2, …, cn
  e1 : a1;
  e2 : a2;
  …
  en : an;
  EN_OTRO_CASO : an+1   // si ninguna ei
FIN_SEGÚN

SI como caso particular

SI e ENTONCES a SI_NO b FIN_SI
  ≡ SEGÚN …  e : a;  NO (e) : b  FIN_SEGÚN

SI e ENTONCES a FIN_SI
  ≡ SEGÚN …  e : a;  NO (e) : ;  FIN_SEGÚN   // acción vacía

Máximo de dos enteros. Especificación: pre {x = X, y = Y}; post {z = máx (X, Y)}. La composición secuencial no permite decidir según los datos: hace falta la alternativa.

Máximo de dos enteros

ALGORITMO
  PRE { x, y : Entero; x = X, y = Y }
  Leer (x, y);
  SEGÚN x, y
    x ≥ y : z ← x;
    x < y : z ← y;
  FIN_SEGÚN;
  Escribir (z)
  POST { x = X, y = Y, ((z = X) O (z = Y)) Y (z ≥ X) Y (z ≥ Y) }
FIN

Ordenar tres enteros distintos (pre: X ≠ Y ≠ Z ≠ X; post: (p, s, t) ∈ perm (X, Y, Z) y p < s < t). El resultado es una de las 3! = 6 permutaciones.

Solución 1: los seis casos (guiada por los datos)

Leer (a, b, c);
SEGÚN a, b, c
  a<b<c : p ← a; s ← b; t ← c;
  a<c<b : p ← a; s ← c; t ← b;
  b<a<c : p ← b; s ← a; t ← c;
  b<c<a : p ← b; s ← c; t ← a;
  c<b<a : p ← c; s ← b; t ← a;
  c<a<b : p ← c; s ← a; t ← b;
FIN_SEGÚN;
Escribir (p, s, t)

Solución 3: guiada por los resultados

p ← a; s ← b; t ← c;
SEGÚN p, s, t
  (p < s) Y (p < t) : ;                 // acción vacía
  (s < p) Y (s < t) : Intercambio (p, s);
  (t < p) Y (t < s) : Intercambio (p, t);
FIN_SEGÚN;
SI s > t ENTONCES Intercambio (s, t) FIN_SI;
Escribir (p, s, t)

La solución 2 anida dos SEGÚN: primero compara a y b y después sitúa c (tres casos en cada rama).

1.6Tipos no primitivos: producto de tipos (registro)

Los valores de un tipo pueden ser atómicos (escalares) o estructurados. Los constructores habituales son la tabla (array), la estructura (producto de tipos) y la secuencia.

Producto de tipos (registro, estructura): sus valores son agregaciones de valores de otros tipos ya definidos. nombre = TIPO < a1: T1; a2: T2; …; aN: TN >. Dominio: las N-tuplas; cardinalidad: C = CT1 · CT2 · … · CTN.

Notación SP

LÉXICO
  Estudiante = TIPO < nombre : secuencia de Carácter;
                      edad : Entero;
                      sexo : Booleano;
                      centro : Entero [1, 20];
                      curso : Entero [1, 6] >;
  a1 : Estudiante;
// a1 = <"J. Gómez", 21, F, 4, 3>
// acceso: a1.curso (o «curso de a1»)

Tema 2

Acciones, funciones y tablas

Parametrización de acciones (dato, resultado, dato–resultado), funciones y composición funcional, ámbito de los identificadores y el tipo tabla.

2.1Acciones parametrizadas

Una acción (procedimiento) describe una acción compleja en función de otras más simples y se usa igual que una primitiva. Su algoritmo combina acciones para modificar el estado del proceso y lograr la postcondición a partir de la precondición.

Motivación: la acción AñoBisiesto sin parámetros sólo sirve para la variable global f. Si tenemos hoy, mañana, ayer: Fecha, ¿cómo la usamos? Parametrizando: «mayor parametrización supone mayor independencia del contexto: más reutilizable».

Acción con un parámetro dato

AñoBisiesto : acción (dato f : Fecha)
  POST { esBisiesto es Verdadero si f.año es bisiesto }
  ALGORITMO
    esBisiesto ← ((f.año MOD 4 = 0) Y (f.año MOD 100 ≠ 0))
                  O (f.año MOD 400 = 0)
  FIN
…
AñoBisiesto (hoy);
AñoBisiesto (mañana);

Intercambio

LÉXICO
  a, b : Entero;
  Intercambio : acción (dato–resultado x, y : Entero)
    LÉXICO
      t : Entero;           // variable local
    ALGORITMO
      t ← x; x ← y; y ← t
    FIN;
ALGORITMO
  Leer (a, b);              { a = A, b = B }
  Intercambio (a, b);       { a = B, b = A }
  Escribir (a, b)
FIN.

Notación: nombre : acción (clase1 p1 : tipo1; …; clasen pn : tipon), donde la clase es dato, resultado o dato–resultado. En la definición están los parámetros formales; en la llamada, los argumentos (parámetros reales).

Valor decimal de un binario de cuatro cifras (versión corregida de las transparencias)

ValDec_NumBin : acción (dato bit3, bit2, bit1, bit0 : Entero [0, 1];
                        resultado valDec : Entero)
  ALGORITMO
    valDec ← bit3*8 + bit2*4 + bit1*2 + bit0
  FIN;
ALGORITMO
  x ← 0; y ← 1;
  ValDec_NumBin (1, 1, 1, 0, vD);   Escribir (vD);   // 14

Traza de la llamada

Al llamar ValDec_NumBin (y, x, y, x, vD): bit3 ← 1, bit2 ← 0, bit1 ← 1, bit0 ← 0 (copias). Se calcula valDec = 8 + 2 = 10 y, al volver, vD ← valDec = 10. Con Intercambio (a, b) y a = 7, b = 4: al entrar x = 7, y = 4; al salir x = 4, y = 7, que se copian a a y b.

Max3 se puede resolver de cuatro formas: (1) composición funcional con Max2; (2) análisis exhaustivo de casos (x mayor que y y que z…); (3) composición funcional con análisis de casos (si x > y, Max2 (x, z); si no, Max2 (y, z)); (4) análisis de casos en dos etapas (SEGÚN x, y y dentro SEGÚN con z). La 1 es la más legible y reutiliza lo ya hecho.

Tema 3

La iteración y sus formas

Por qué hace falta iterar, las cuatro composiciones iterativas de la notación, sus equivalencias y los problemas clásicos resueltos.

3.1La necesidad de iterar

Problema: calcular la media de las notas de un grupo cuyo tamaño no se conoce; se termina con una nota negativa. Con SI anidados habría que escribir el mismo bloque «sumar, contar, leer» tantas veces como alumnos… que no sabemos. Hace falta repetir.

Partes de toda iteración

  • Inicialización: tratamientos previos.
  • Cuerpo: las sentencias que se repiten.
  • Finalización: lo que se hace cuando la iteración se detiene.

Y siempre debe tener un punto de parada.

3.2MIENTRAS

MIENTRAS cond HACER S FIN_MIENTRAS: comprobación de parada al principio; la condición es de continuación. El cuerpo puede ejecutarse cero veces.

Media de notas con MIENTRAS

suma ← 0; numElem ← 0; Leer (nota);
MIENTRAS nota ≥ 0 HACER
  suma ← suma + nota; numElem ← numElem + 1;
  Leer (nota)
FIN_MIENTRAS;
SI numElem > 0 ENTONCES Escribir ("Valor medio de las notas: ", suma / numElem)
SI_NO Escribir ("No hay notas que promediar")
FIN_SI

3.3REPETIR … HASTA

REPETIR S HASTA cond: parada al final; el cuerpo se ejecuta al menos una vez; la condición es de parada (al revés que en el MIENTRAS). Ideal cuando hay que hacer algo antes de poder comprobar: pedir un dato hasta que sea válido.

Validar una nota

REPETIR
  Escribir ("Ingrese la nota del alumno (0 a 10): ");
  Leer (nota);
  SI (nota < 0) O (nota > 10) ENTONCES
    Escribir ("Error: la nota debe estar entre 0 y 10.")
  FIN_SI
HASTA QUE (nota ≥ 0) Y (nota ≤ 10);
Escribir ("Nota registrada con éxito: ", nota)

3.4ITERAR … DETENER

ITERAR S2 DETENER cond S3 FIN_ITERAR: parada en medio. S2 se ejecuta al menos una vez y S3 puede no ejecutarse. La condición es de parada. Encaja con «leer, comprobar si es el final, tratar».

Media de notas con ITERAR

suma ← 0; numElem ← 0;
ITERAR
  Leer (nota);
  DETENER nota < 0;
  suma ← suma + nota; numElem ← numElem + 1
FIN_ITERAR;
SI numElem > 0 ENTONCES Escribir ("Valor medio: ", suma / numElem)
SI_NO Escribir ("No hay notas que promediar") FIN_SI

3.5Equivalencias

Cualquier composición iterativa se puede expresar con cualquier otra; hay que saber elegir la adecuada.

ComposiciónEquivalente con…Equivalente con…
MIENTRAS c HACER S2SI c ENTONCES REPETIR S2 HASTA NO c FIN_SIITERAR DETENER NO c; S2 FIN_ITERAR
REPETIR S2 HASTA cS2; MIENTRAS NO c HACER S2ITERAR S2 DETENER c FIN_ITERAR
ITERAR S2 DETENER c S3S2; MIENTRAS NO c HACER S3; S2S2; SI NO c ENTONCES REPETIR S3; S2 HASTA c FIN_SI

Ojo

Al pasar de MIENTRAS a REPETIR (o al revés) la condición se niega: una es de continuación y la otra de parada. Y el REPETIR necesita un SI delante porque el MIENTRAS puede no entrar nunca.

3.6RECORRIENDO

k RECORRIENDO [a, b] HACER S FIN_RECORRIENDO: ejecuta S una vez por cada valor del intervalo, con k tomando a, a+1, …, b. El inicio y la parada están implícitos. Si a > b el intervalo es vacío y S no se ejecuta. Variante: EN SENTIDO INVERSO (de b a a).

  • S no debe modificar la variable de control k.
  • No debe suponerse que los límites se reevalúan en cada vuelta; es sano que no cambien.
  • Al terminar, el valor de k no está definido (como si no estuviera inicializada).

Producto de dos naturales sólo con sumas

3.7Problemas iterativos resueltos

Factorial

0! = 1 y n! = n · (n − 1)!. Tres versiones:

Versión 1 (MIENTRAS)

Leer (n);
fact ← 1; i ← 1;
MIENTRAS i < n HACER
  i ← i + 1;
  fact ← fact * i
FIN_MIENTRAS;
Escribir (fact)

Versión 3 (RECORRIENDO)

Leer (n);
fact ← 1;
i RECORRIENDO [2, n] HACER
  fact ← fact * i
FIN_RECORRIENDO;
Escribir (fact)
¿Cuál de las versiones es más apropiada y por qué?

La de RECORRIENDO: el número de multiplicaciones se conoce antes de empezar (n − 1), así que la composición expresa directamente la idea y no hay que gestionar a mano el contador ni la condición. Además funciona sin casos especiales para n = 0 y n = 1 (el intervalo [2, n] es vacío y fact queda en 1).

Divisores propios y números primos

Divisores propios de a

Leer (a); n ← 0;

  SI a MOD i = 0 ENTONCES
    Escribir (i); n ← n + 1
  FIN_SI
FIN_RECORRIENDO;
Escribir (n)

¿Es n primo? (búsqueda del primer divisor)

Leer (n);
SI n = 1 ENTONCES Escribir ("1 no es primo")
SI_NO
  j ← 2;
  MIENTRAS n MOD j ≠ 0 HACER j ← j + 1 FIN_MIENTRAS;
  SI j = n ENTONCES Escribir (n, " es primo")

FIN_SI
¿Hay formas mejores?
  • Divisores: ningún divisor propio supera a/2, así que basta i RECORRIENDO [2, a DIV 2]; mejor aún, recorrer hasta √a y anotar cada pareja i y a DIV i.
  • Primos: es una búsqueda con garantía de éxito (n siempre se divide a sí mismo), por eso no hace falta comprobar el final. Mejoras de la práctica 5: descartar los pares (salvo el 2) y probar sólo divisores impares hasta √n: si no hay divisor por debajo de la raíz, tampoco por encima.
  • Ojo: las transparencias escriben «1 es primo», pero el 1 no es primo por definición (sólo tiene un divisor).

Potencias de 2 en [x, y]

Solución 1: una función potencia

    p ← 1;

  Escribir ("La potencia ", i, "-ésima de 2 es ", potencia2);

¿Cuál es la diferencia fundamental entre las dos versiones?

La primera recalcula cada potencia desde cero (P2 (i) hace i multiplicaciones: en total del orden de y² / 2). La segunda reutiliza la anterior: cada término sale del previo con una sola multiplicación (del orden de y en total). Es la idea que reaparece en la serie de ex de la práctica 5: calcular cada término a partir del anterior.

Parte entera de la raíz cuadrada

Se recorren los cuadrados 1, 4, 9, 16… sumando impares (1 = 1, 1 + 3 = 4, 1 + 3 + 5 = 9…: la suma de los k primeros impares es k²).

Raíz entera por suma de impares

  c ← c + imp;

Escribir (rc)       // n = 10: c = 1, 4, 9, 16 → rc = 3

Tema 4

Composición iterativa y noción de secuencia

La máquina secuencial, el invariante, los esquemas de recorrido y de búsqueda, cómo se combinan y los modelos de acceso secuencial. Incluye un simulador para ver los esquemas paso a paso.

4.1Secuencias y máquina secuencial

Una secuencia es un conjunto de valores de cualquier tipo en el que importa el orden: [32, 64, 85] ≠ [85, 64, 32]. Su longitud (nº de elementos) no se conoce a priori; [ ] es la secuencia vacía (long = 0).

La máquina secuencial es una cinta con una ventana que deja ver un único elemento, el elemento actual (EA). A su izquierda queda la parte izquierda (Piz, lo ya tratado) y a su derecha la parte derecha (Pdr, lo pendiente). En las secuencias marcadas, tras el último elemento hay una marca de fin (MarcaFin, por ejemplo '#').

Primitiva (primer modelo)Efecto
Comenzar (S)Inicia la consulta; el primer elemento pasa a ser el EA
Avanzar (S)Avanza al siguiente elemento
EA (S)Devuelve el elemento actual (MarcaFin al final)
Crear (S)Crea S vacía para añadir elementos por la derecha
Registrar (S, e)Graba e como último elemento
Marcar (S)Graba la marca de fin

En las secuencias no marcadas se usa una función booleana FDS (S) (fin de secuencia), verdadera cuando se ha sobrepasado el último elemento.

En C++ (práctica 6)

La entrada estándar hace de secuencia del primer modelo: cin >> EA antes del bucle es Comenzar, while (EA != MF) la comprobación de la marca y otra lectura al final del cuerpo es Avanzar.

4.2Análisis iterativo y el invariante

Una iteración se modela como el tratamiento de una secuencia. Los estados intermedios no son iguales, pero todos comparten una propiedad que se cumple en cada paso: el invariante. Al terminar, invariante + condición de parada ⇒ postcondición.

Longitud de un texto

Léxico
  conta : Entero ≥ 0;
  S : secuencia de Carácter;
Algoritmo
  Comenzar (S); conta ← 0;               // inicialización
  MIENTRAS EA (S) ≠ MarcaFin HACER
    conta ← conta + 1; Avanzar (S)       // cuerpo
  FIN_MIENTRAS;
  Escribir (conta)                        // finalización
Fin.
// Inv: conta = número de elementos de Piz (S)

Cómo se obtiene cada parte (razonamiento inductivo)

  • Inicialización: para cada variable v, ¿cuál es la solución para la secuencia vacía? (casos base: conta ← 0, suma ← 0).
  • Tratamiento elemental: suponemos conocida la solución para Piz, guardada en v (hipótesis de inducción); ¿qué hay que hacer para tener la de Piz más el EA? v ← g (v, EA): suma ← suma + EA (S), numElem ← numElem + 1.

Ejemplo: media de una secuencia de notas. Post: { suma = ΣSi, numElem = long (S) }. Al final, si numElem > 0 se escribe suma / numElem; si no, «Secuencia vacía».

4.3Esquemas de recorrido

Un esquema algorítmico es una plantilla aplicable a una clase de problemas. Recorrido (enumeración secuencial): aplicar el mismo tratamiento a todos los elementos. Hay que decidir si:

  • H1: la secuencia vacía se puede tratar como las demás.
  • H2: el primer elemento se puede tratar como los demás.

Esquema 1 · H1 y H2

Comenzar;
{ Inicialización del tratamiento }
MIENTRAS EA ≠ MarcaFin HACER
  { Tratamiento de EA }
  Avanzar
FIN_MIENTRAS;
{ Terminación del tratamiento }

Esquema 2 · ¬H1 y H2

Comenzar;
SEGÚN EA
  EA = MarcaFin : { Tratamiento sec. vacía }
  EA ≠ MarcaFin :
    { Inicialización del tratamiento }
    REPETIR
      { Tratamiento de EA }
      Avanzar
    HASTA EA = MarcaFin;
    { Terminación del tratamiento }
FIN_SEGÚN

Esquema 3 · ¬H1 y ¬H2

Comenzar;
SEGÚN EA
  EA = MarcaFin : { Tratamiento sec. vacía }
  EA ≠ MarcaFin :
    { Tratamiento del 1er elemento }      // casos base: secuencia de un elemento
    ITERAR
      Avanzar
      DETENER EA = MarcaFin;
      { Tratamiento de EA }
    FIN_ITERAR;
    { Terminación del tratamiento }
FIN_SEGÚN

Con la media: esquema 1 (sum ← 0; n ← 0; al final SEGÚN n = 0 / n > 0); esquema 2 (la secuencia vacía se trata al principio y la división se hace sin comprobar); esquema 3 (sum ← EA (S); n ← 1 como inicialización).

Meseta mayor

Meseta = sucesión de valores idénticos. En S = [35, 18, 18, 18, 5, 62, 35, 35, 11, 11, 11, 11, 9, 9] la mayor mide 4 (los 11). Inv: { p = LongMesetaMayor (Piz), u = último (Piz), m = LongÚltMeseta (Piz) }. u no está definido para la secuencia vacía (¬H2), así que hay dos opciones:

Con H2 (esquema 1), enteros > 0

Comenzar (S);
p ← 0; m ← 0; u ← 0;   // «truco sucio»: 0 no aparece

  u ← EA (S);
  Avanzar (S)

Escribir (p)

Con ¬H2 (esquema 3)

En cada paso se registra el mayor de los dos EA (o los dos si son iguales) y se avanza en esa secuencia; cuando una se acaba se copia el resto de la otra con la acción CopiarResto.

Intercalar

Comenzar (S1); Comenzar (S2); Crear (R);
MIENTRAS (EA (S1) ≠ MarcaFin) Y (EA (S2) ≠ MarcaFin) HACER
  SEGÚN EA (S1), EA (S2)
    EA (S1) = EA (S2) : Registrar (R, EA (S1)); Registrar (R, EA (S2));
                        Avanzar (S1); Avanzar (S2);
    EA (S1) > EA (S2) : Registrar (R, EA (S1)); Avanzar (S1);
    EA (S1) < EA (S2) : Registrar (R, EA (S2)); Avanzar (S2);
  FIN_SEGÚN
FIN_MIENTRAS;
SEGÚN EA (S1), EA (S2)
  (EA (S1) ≠ MarcaFin) Y (EA (S2) = MarcaFin) : CopiarResto (S1, R);
  (EA (S1) = MarcaFin) Y (EA (S2) ≠ MarcaFin) : CopiarResto (S2, R);
  EN_OTRO_CASO : ;
FIN_SEGÚN;
Marcar (R)

4.5Esquema de búsqueda

Búsqueda: encontrar el primer elemento que cumple una propiedad Pro (no hace falta recorrer todo).

  • Post: { (Pro (EA) = Verdadero O EA = MarcaFin) Y ningún e de Piz cumple Pro }
  • Inv: { ningún elemento de Piz cumple Pro }
  • Condición de continuación: (EA ≠ MarcaFin) Y NO Pro (EA)

Esquema de búsqueda

Comenzar;  { Establecimiento inicial del invariante }
MIENTRAS (EA ≠ MarcaFin) Y NO Pro (EA) HACER
  { Tratamientos para mantener el invariante }   // si Pro depende de Piz
  Avanzar
FIN_MIENTRAS;
SEGÚN EA
  EA = MarcaFin : { Tratamiento: no encontrado }
  EA ≠ MarcaFin : { Tratamiento: EA encontrado }
FIN_SEGÚN

YDESPUÉS

Si es erróneo consultar Pro en la marca (o no hay marca y se usa FDS), se usa el Y condicional: MIENTRAS (EA ≠ MarcaFin) YDESPUÉS NO Pro (EA) sólo evalúa la segunda parte si la primera es verdadera. En C++, && ya funciona así.

Al menos x apariciones de c: Pro depende de Piz (la x-ésima c). Inv: { noc = NroOcur (c, Piz) Y noc < x }.

Búsqueda con tratamiento

Comenzar (S); Leer (x, c); noc ← 0;
MIENTRAS (EA (S) ≠ MarcaFin) Y ((EA (S) ≠ c) O (noc ≠ x – 1)) HACER
  SI EA (S) = c ENTONCES noc ← noc + 1 FIN_SI;   // mantener el invariante
  Avanzar (S)
FIN_MIENTRAS;
SEGÚN EA (S)
  EA (S) = MarcaFin : Escribir (c, " no aparece ", x, " veces");
  EA (S) ≠ MarcaFin : Escribir (c, " aparece al menos ", x, " veces")
FIN_SEGÚN

Búsqueda con garantía de éxito: si se sabe que algún elemento cumple Pro, se omite la comparación con la marca. Ejemplo: ¿un texto es blanco? MIENTRAS EA (S) = ' ' HACER Avanzar (S) (la marca no es un blanco, así que para seguro).

Longitud de la primera palabra: doble búsqueda; la del comienzo (saltar blancos, con garantía de éxito) y la del final, contando: lpp ← 0; MIENTRAS (EA (S) ≠ MarcaFin) Y (EA (S) ≠ ' ') HACER lpp ← lpp + 1; Avanzar (S).

¿Se podría usar REPETIR en la segunda búsqueda?

Sí: cuando empieza, ya sabemos que EA no es la marca ni un blanco (hay palabra), así que el cuerpo se ejecuta al menos una vez y REPETIR lpp ← lpp + 1; Avanzar (S) HASTA (EA (S) = MarcaFin) O (EA (S) = ' ') es correcto y expresa esa certeza. El MIENTRAS también es correcto y sigue el esquema general de búsqueda.

¿Contiene 'A', 'E' e 'I' en este orden? Tres búsquedas iguales: se define una acción (las secuencias se pasan como dato–resultado, porque avanzar cambia su estado interno).

Cuestiones de la transparencia
  • ¿Sería correcto llamar a BuscarLetra tres veces seguidas y comprobar sólo al final? Sí: si una búsqueda llega a la marca, las siguientes no avanzan (su condición es falsa) y al final EA = MarcaFin → «No».
  • ¿Y para 'A', 'A', 'E'? Ninguna de las dos versiones sirve: tras encontrar la primera 'A', la segunda búsqueda de 'A' la encuentra en el mismo sitio sin avanzar.
  • ¿Cómo arreglarlo en el algoritmo principal? Haciendo Avanzar (S) después de cada búsqueda con éxito, antes de la siguiente.
  • ¿Y modificando la acción? Empezando con un Avanzar; entonces cambia su especificación: Pre { EA (S) ≠ MarcaFin } y la Post habla del primer c a la derecha del EA inicial (la primera búsqueda tendría que hacerse aparte o con otra acción).

Igualdad de dos secuencias: búsqueda de la primera diferencia recorriéndolas a la vez (Inv: Piz (S1) = Piz (S2)); son iguales si las dos acaban en la marca a la vez.

4.6Combinación de recorrido y búsqueda

Hay que identificar la naturaleza de cada subproblema y cómo se combinan: anidado (uno forma parte del tratamiento del EA del otro) o en secuencia (uno detrás del otro).

Anidados: elementos de S1 que están en S2 (ambas decrecientes, sin repetidos)

Comenzar (S1); Comenzar (S2);
MIENTRAS EA (S1) ≠ MarcaFin HACER                       // 1) recorrido de S1
  MIENTRAS (EA (S2) ≠ MarcaFin) Y (EA (S2) > EA (S1)) HACER
    Avanzar (S2)                                        // 2) búsqueda en S2
  FIN_MIENTRAS;
  SI (EA (S2) ≠ MarcaFin) Y (EA (S2) = EA (S1)) ENTONCES
    Escribir (EA (S1), " está también en S2")
  SI_NO Escribir (EA (S1), " no está en S2") FIN_SI;
  Avanzar (S1)
FIN_MIENTRAS

En secuencia: ¿hay en S2 un elemento igual a la suma de S1?

Comenzar (S1);
SEGÚN EA (S1)
  EA (S1) = MarcaFin : Escribir ("Secuencia S1 vacía");
  EA (S1) ≠ MarcaFin :
    suma ← EA (S1);
    ITERAR                                  // 1) recorrido de S1 (¬H1, ¬H2)
      Avanzar (S1)
      DETENER EA (S1) = MarcaFin;
      suma ← suma + EA (S1)
    FIN_ITERAR;
    Comenzar (S2);                          // 2) búsqueda en S2, en secuencia
    MIENTRAS (EA (S2) ≠ MarcaFin) Y (EA (S2) ≠ suma) HACER
      Avanzar (S2)
    FIN_MIENTRAS;
    SI EA (S2) = MarcaFin ENTONCES Escribir ("No") SI_NO Escribir ("Sí") FIN_SI
FIN_SEGÚN
Traza manual del primer algoritmo

a) S1 = [30, 24, 12, 6, 5], S2 = [60, 58, 30, 15, 12, 3, 2]: 30 sí (S2 avanza 60, 58 y para en 30); 24 no (para en 15); 12 sí; 6 no (para en 3); 5 no.

b) S1 = [60, 58, 30, 15, 12, 3, 2], S2 = [30, 24, 12, 6, 5]: 60 no y 58 no (S2 está en 30, que no es mayor); 30 sí; 15 no (S2 avanza a 12); 12 sí; 3 no (S2 llega a la marca); 2 no.

Como S2 está ordenada, cada búsqueda continúa donde quedó la anterior: S2 se recorre una sola vez en total.

    Una secuencia S de longitud L con elementos de tipo Tb se guarda en una tabla T de ese mismo tipo. El tamaño de la tabla, LMAX, es una constante y tiene que ser:

    Lo que hay detrás de la secuencia es basura

    La tabla tiene LMAX casillas, pero sólo las L primeras (más la marca) son de la secuencia. Las demás tienen lo que hubiera en memoria: nunca se miran. Por eso o la marca o long son imprescindibles.

    Devuelve (i, j) o (0, 0)

    PosEnTabla : función (m : MatrizCar; car : Carácter) → Posición;

  POST { (i, j) si car está en m; (0, 0) si no está }

    5.5Algoritmos de ordenación

    Ordenar una colección A = {a1, …, an} es obtener una permutación suya que cumpla un criterio. Cada elemento es un registro con un campo clave por el que se ordena: {(Luis, 29), (Ana, 45), (Víctor, 18), (Fernando, 24)} ordenado por nombre o por edad da dos permutaciones distintas. Se estudian los métodos directos de clasificación interna (todo en una tabla en memoria), que hacen del orden de n² comparaciones.

    Tipos de los algoritmos

    TipoClave = Entero;
TipoDatos = TIPO < clave : TipoClave; (* otros campos *) >;
TipoIndice = Entero [1, n];
a : TABLA [TipoIndice] DE TipoDatos;

    Todos mantienen la tabla partida en dos: una parte ordenada a la izquierda que crece en cada paso y una desordenada a la derecha que mengua.

    Inserción directa

    En el paso q, los q − 1 primeros ya están ordenados (entre sí): se toma a[q] y se inserta en su sitio dentro de la parte ordenada, desplazando una posición a la derecha los mayores que él. Invariante: Ordenado(q) y Permuta(a, a′, q) (los q primeros están ordenados y son los mismos que había, en otro orden).

    Inserción directa con centinela

    TipoIndice = Entero [0, n];      // la posición 0 es el centinela
ALGORITMO
  q RECORRIENDO [2, n] HACER
    a[0] ← a[q];                 // centinela
    j ← q − 1;
    MIENTRAS a[0].clave < a[j].clave HACER
      a[j + 1] ← a[j];           // desplazamiento
      j ← j − 1
    FIN_MIENTRAS;
    a[j + 1] ← a[0]
  FIN_RECORRIENDO
FIN.

    C++ (sin centinela: la tabla empieza en 0)

    void InsercionDirecta (Tabla a, int n) {
    int q, j, x;
    for (q = 1; q < n; q = q + 1) {
        x = a[q];
        j = q - 1;
        while ((j >= 0) && (x < a[j])) {
            a[j+1] = a[j];       // desplazamiento
            j = j - 1;
        }
        a[j+1] = x;
    }
}

    Para qué sirve el centinela

    Copiando a[q] en a[0], el MIENTRAS se para seguro al llegar a 0 (a[0].clave < a[0].clave es falso) y no hace falta preguntar j ≥ 1 en cada vuelta: una comparación menos por iteración. En C++ los índices empiezan en 0 y no hay casilla libre, así que se pregunta j >= 0 (y el && evita leer a[−1]).

    Inserción binaria

    Igual que la directa, pero la posición de inserción se busca con una búsqueda binaria en la parte ordenada (se mira el elemento central y se descarta la mitad). Ahorra comparaciones, pero no desplazamientos: sigue siendo O(n²).

    Inserción binaria

    i RECORRIENDO [2, n] HACER
  inf ← 1; sup ← i − 1; x ← a[i];
  MIENTRAS inf ≤ sup HACER              // búsqueda binaria
    med ← (inf + sup) DIV 2;
    SI x.clave < a[med].clave ENTONCES sup ← med − 1
    SI_NO inf ← med + 1
    FIN_SI
  FIN_MIENTRAS;
  j RECORRIENDO [inf, i − 1] EN_SENTIDO_INVERSO HACER
    a[j + 1] ← a[j]                     // desplazamiento
  FIN_RECORRIENDO;
  a[inf] ← x
FIN_RECORRIENDO

    El desplazamiento va de derecha a izquierda

    Si se recorriera [inf, i − 1] hacia delante, a[inf + 1] ← a[inf] machacaría el siguiente antes de moverlo. Por eso es EN_SENTIDO_INVERSO. Y como el SI_NO incluye la igualdad, los iguales quedan en su orden original (el método es estable).

    Selección directa

    En el paso q se selecciona el menor de la parte desordenada a[q..n] y se intercambia con a[q]. Invariante: Ordenado(q) y Partición(q): los q primeros están ordenados y son los q menores de toda la tabla (ningún elemento de la derecha es menor que uno de la izquierda). Por eso al final del paso n − 1 el último ya está en su sitio.

    Selección directa

    q RECORRIENDO [1, n − 1] HACER
  pos ← q; min ← a[q];
  j RECORRIENDO [q + 1, n] HACER
    SI min.clave > a[j].clave ENTONCES
      pos ← j; min ← a[j]
    FIN_SI
  FIN_RECORRIENDO;
  a[pos] ← a[q];                 // intercambio
  a[q] ← min
FIN_RECORRIENDO

    C++

    void SeleccionDirecta (Tabla a, int n) {
    int q, j, pos, min;
    for (q = 0; q < n - 1; q = q + 1) {
        pos = q; min = a[q];
        for (j = q + 1; j < n; j = j + 1) {
            if (a[j] < min) { pos = j; min = a[j]; }
        }
        a[pos] = a[q];           // intercambio
        a[q] = min;
    }
}

    Si tras el paso q los primeros elementos son los menores de toda la tabla (6, 8, 12…), es selección. Si sólo están ordenados entre sí pero aún puede llegar uno menor (15, 21, 32 y luego aparece el 8), es inserción.
