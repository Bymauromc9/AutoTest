          Práctica 5

          Teoría y órdenes

          Lo que hace Gram-Schmidt, qué guardan Q y R y cómo se pide en SageMath.

          0.1Gram-Schmidt y QR en SageMath

          Gram-Schmidt: w₁ = u₁ y wₖ = uₖ − Σ (uₖ·wⱼ / wⱼ·wⱼ) wⱼ; después vₖ = wₖ / ‖wₖ‖. En la factorización A = Q·R, Q tiene por columnas esa base ortonormal de C(A) (Qᵗ·Q = I) y R = Qᵗ·A es triangular superior: su columna j son las coordenadas de la columna j de A en la base de Q.

          Órdenes

          • u.dot_product(w) (o u*w), w.normalized(), w.norm().
          • Q, R = A.QR() si A es cuadrada; A.QR(full=False) si no (si no se pone, Q sale m × m completada y R con filas de ceros). La matriz tiene que estar sobre un cuerpo con raíces: QQbar o AA (exacto) o RDF (decimales).
          • load('triangular.sage') carga resolucion_triangular; from geometria import * los dibujos.

          Los números con «?»

          Sobre QQbar, SageMath escribe 0.7071067811865475? : es un número exacto (aquí √2/2) del que muestra sólo los decimales. Sobre RDF los resultados son aproximados (1.0000000000000004).

          Ejercicio 1 (a) · {(1, 1), (1, 3)}

          {(1, 1), (1, 3)} ⊆ ℝ².

          Resolución explicada

          A = 1113 tiene det 2 ≠ 0: independientes. Gram-Schmidt: w₁ = (1, 1), w₂ = (1, 3) − (4/2)(1, 1) = (−1, 1). Normalizando y R = QᵗA:

          Q = √2/2−√2/2√2/2√2/2, R = √22√20√2

          Interpretación: (1, 1) = √2·q₁ (primera columna de R) y (1, 3) = 2√2·q₁ + √2·q₂ (segunda columna).

          Ejercicio 1 (d) · dos vectores de ℝ³: full=False

          {(1, 1, 0), (1, 2, 1)} ⊆ ℝ³.

          Resolución explicada

          Independientes. Como en el apartado (b) para los dos primeros: Q = (q₁ | q₂) con q₁ = (1, 1, 0)/√2 y q₂ = (−1, 1, 2)/√6, y R = √23√2/20√6/2.

          La trampa de full

          Con A.QR() sobre una matriz 3 × 2, SageMath completa Q a una base ortonormal de todo ℝ³ (añade (1, −1, 1)/√3) y R sale 3 × 2 con una fila de ceros. Para la QR «reducida» de clase hay que pedir A.QR(full=False).

          Ejercicio 1 (e) · propuesto: vectores dependientes

          {(1, 1, 0), (1, 2, 1), (2, 3, 1)} ⊆ ℝ³.

          Resolución explicada

          (2, 3, 1) = (1, 1, 0) + (1, 2, 1): no son independientes (rango 2). Gram-Schmidt da w₃ = 0 y no se puede normalizar: la QR de clase exige columnas independientes. Lo correcto es quitar el vector sobrante; la base ortonormal de ⟨u₁, u₂, u₃⟩ es la del apartado (d), {(1, 1, 0)/√2, (−1, 1, 2)/√6}, y R sería 2 × 3 con tercera columna (q₁·u₃, q₂·u₃) = (5√2/2, √6/2).

          Ejercicio 2 · Descomposición ortogonal

          Escribir v como un vector de W más otro perpendicular a W, usando la Q de una QR.

          2.0Método

          1. QR de la matriz con una base de W por columnas: las columnas de Q son una base ortonormal de W.
          2. vW = (v·q₁)q₁ + ⋯ + (v·qr)qr = Q·Qᵗ·v.
          3. v⊥ = v − vW.
          Ejercicio 2 (a) y (d) · W = ⟨(1, 2, 1), (1, 1, 0)⟩, v = (1, 1, 1)

          W = ⟨(1, 2, 1), (1, 1, 0)⟩ y v = (1, 1, 1). (El apartado (d) del cuaderno es el mismo.)

          Resolución explicada

          Base ortonormal de W: q₁ = (1, 2, 1)/√6, q₂ = (1, 0, −1)/√2. v·q₁ = 4/√6 y v·q₂ = 0:

          vW = 46(1, 2, 1) = (2/3, 4/3, 2/3), v⊥ = (1/3, −1/3, 1/3)

          Resultado(1, 1, 1) = (2/3, 4/3, 2/3) + (1/3, −1/3, 1/3)

          Ejercicio 2 (b, c) · propuestos

          b) W = ⟨(1, 2, 1)⟩, v = (1, 1, 1). c) W = ⟨(1, 2, 1, 0), (1, 1, 0, 1)⟩, v = (2, 1, 1, 1).

          Resolución explicada

          b) Una recta: vW = (v·u/u·u)u = (4/6)(1, 2, 1).

          Resultadob) (1, 1, 1) = (2/3, 4/3, 2/3) + (1/3, −1/3, 1/3)

          c) Base ortonormal: q₁ = (1, 2, 1, 0)/√6 y q₂ = (1, 0, −1, 2)/√6 (Gram-Schmidt: (1, 1, 0, 1) − ½(1, 2, 1, 0) = ½(1, 0, −1, 2)). v·q₁ = 5/√6, v·q₂ = 3/√6:

          Ejercicio 4 · Coordenadas de proyecciones

          Las coordenadas de la proyección de v en la base ortonormal Q son c = Qᵗ·v, y la proyección es Q·c.

          Ejercicio 4 (a) · W = ⟨(1, 2, 1), (1, 1, 0)⟩, v = (4, 5, 2)

          W = ⟨(1, 2, 1), (1, 1, 0)⟩ y v = (4, 5, 2).

          Resolución explicada

          q₁ = (1, 2, 1)/√6, q₂ = (1, 0, −1)/√2. c = Qᵗv = (16/√6, 2/√2) = (8√6/3, √2) ≈ (6,532, 1,414), y

          ResultadoproyW(v) = Q·c = (11/3, 16/3, 5/3) ≈ (3,667, 5,333, 1,667)

          Ejercicio 4 (b, c) · propuestos

          b) W = ⟨(1, 2, 1, 0), (1, 1, 0, 1)⟩, v = (0, 1, 1, −1). c) W = ⟨(1, 2, 1), (1, 1, 1), (1, 1, 0)⟩, v = (1, 1, 1).

          Resolución explicada

          b) Con q₁ = (1, 2, 1, 0)/√6 y q₂ = (1, 0, −1, 2)/√6: c = (3/√6, −3/√6) = (√6/2, −√6/2) y la proyección es (0, 1, 1, −1) = v. Tiene sentido: v = (1, 2, 1, 0) − (1, 1, 0, 1) ya está en W.

          Ejercicio 5 · Estabilidad: LU frente a QR

          Una familia de matrices en la que Gauss hace crecer los números como 2ⁿ⁻¹ y la LU pierde toda la precisión.

          Ejercicio 5 · la matriz de Wilkinson

          Aₙ tiene 1 en la diagonal, −1 debajo y 1 en la última columna. Para n = 5, 10, …, 100: construye b para que la solución exacta sea (1, …, 1), resuelve con LU y con QR, calcula el error ‖x − xexacto‖ y compáralos. ¿Qué relación tiene con el factor de crecimiento 2ⁿ⁻¹?

          Resolución explicada

          Al escalonar, la última columna se duplica en cada paso (1, 2, 4, 8, …): el último pivote vale 2ⁿ⁻¹. Con n = 60 eso es ~10¹⁷, más de lo que distingue un número de coma flotante (unas 16 cifras), y la LU devuelve basura (error ≈ 17 en el cuaderno). La QR usa transformaciones ortogonales, que no agrandan los números, y mantiene errores de 10⁻¹⁴.

          Ejercicio 5

          load('triangular.sage')
def prueba(n):
    A = matrix(RDF, n, n)
    for i in range(n):
        A[i, i] = 1; A[i, n - 1] = 1
        for j in range(i): A[i, j] = -1
    x = vector(RDF, [1] * n); b = A * x
    P, L, U = A.LU()
    xlu = vector(resolucion_triangular(U, resolucion_triangular(L, P.transpose() * b, inferior=True)).list())
    Q, R = A.QR()
    xqr = vector(resolucion_triangular(R, Q.transpose() * b).list())
    return (xlu - x).norm(), (xqr - x).norm()
for n in [5, 10, 20, 40, 50, 55, 60, 80, 100]:
    elu, eqr = prueba(n)
    print(f"n = {n:3}: error LU {elu:9.2e}   error QR {eqr:9.2e}   2^(n-1) = {2.0^(n-1):.1e}")

          Hasta n ≈ 50 las dos van bien; a partir de ahí el error de la LU se dispara, justo cuando 2ⁿ⁻¹ supera 10¹⁶. Conclusión: LU es más rápida, pero QR es más estable numéricamente.
