            Práctica 3

            La descomposición LU

            Gauss guardando los multiplicadores: A = L·U con L triangular inferior (unos en la diagonal) y U triangular superior.

            0.1Cómo se calcula a mano

            Si para escalonar A no hace falta intercambiar filas, A = L·U, donde U es la escalonada que da Gauss y L guarda en cada posición (i, j) el multiplicador lᵢⱼ que se usó para hacer cero esa entrada (Fᵢ − lᵢⱼFⱼ).

            Ejemplo del cuaderno

            2114−60−272 F₂ − 2F₁~ 2110−8−2−272 F₃ + F₁~ 2110−8−2083 F₃ + F₂~ 2110−8−2001 = U

            Los multiplicadores son l₂₁ = 2, l₃₁ = −1 (se sumó F₁, es decir, se restó −1·F₁) y l₃₂ = −1:

            A = 100210−1−112110−8−2001

            Para resolver A·x = b se hacen dos sistemas triangulares: L·y = b (hacia delante) y U·x = y (hacia atrás). La factorización se hace una vez y sirve para todos los b.

            Órdenes

            P, L, U = A.LU(pivot='nonzero') devuelve además una matriz de permutación P (A = P·L·U): con pivot='nonzero' sólo intercambia filas si encuentra un pivote 0, así que en estos ejercicios P = I. Para el examen se da resolucion_triangular:

            LU paso a paso y resolucion_triangular (ejecútala primero)

            def resolucion_triangular(M, b, inferior=False):
    """Resuelve M x = b con M triangular; b puede ser vector o lista. Devuelve una matriz fila."""
    n = M.nrows()
    x = [0 for i in range(n)]
    b = vector(b)
    if inferior:
        for i in range(n):
            x[i] = (b[i] - sum(M[i, j] * x[j] for j in range(i))) / M[i, i]
    else:
        for i in range(n - 1, -1, -1):
            x[i] = (b[i] - sum(M[i, j] * x[j] for j in range(i + 1, n))) / M[i, i]
    return matrix([a for a in x])
A = matrix(QQ, [[2, 1, 1], [4, -6, 0], [-2, 7, 2]])
U = copy(A); n = A.nrows(); L = identity_matrix(QQ, n)
for j in range(n - 1):
    for i in range(j + 1, n):
        l = U[i, j] / U[j, j]          # multiplicador
        L[i, j] = l
        U[i, :] = U[i, :] - l * U[j, :]
show("L =", L, "  U =", U, "  L·U == A:", L * U == A)

            Ejercicio 1 · Resolver con LU

            Sistemas de 4, 10 y 40 incógnitas y coordenadas en una base, en dos pasos.

            Ejercicio 1 (a) · tres sistemas con LU

            Usa A.LU(pivot='nonzero') para resolver en dos pasos los tres sistemas de ejercicio1LUMatrices.sobj y ejercicio1LUIndependientes.sobj.

            Resolución explicada

            Ejercicio 1 (a)

            A, B, C = load('ejercicio1LUMatrices.sobj')
a, b, c = load('ejercicio1LUIndependientes.sobj')
print(A.nrows(), B.nrows(), C.nrows())
P, L, U = A.LU(pivot='nonzero')
show("L =", L, "  U =", U)
y = L.solve_right(vector(a))          # L y = a
x = U.solve_right(y)                  # U x = y
show(y, x, A.solve_right(vector(a)))
for M, v in [(B, b), (C, c)]:
    P, L, U = M.LU(pivot='nonzero')
    y = resolucion_triangular(L, v, inferior=True)
    x = resolucion_triangular(U, y)
    print(M.nrows(), vector(x) == M.solve_right(vector(v)))

            Las tres formas dan lo mismo. En cuanto a tiempos, solve_right ya hace una LU internamente con código optimizado, así que para un solo sistema no se gana nada factorizando a mano; la ventaja aparece cuando hay que resolver muchos sistemas con la misma matriz (ejercicio 7).

            Ejercicio 1 (b) · coordenadas en una base con LU

            En ℝ³, con la base B = {(1, 2, 1), (2, 1, 1), (1, 1, 2)}, calcula con la LU las coordenadas de (1, 2, 3), (−2, 1, 3), (4, −2, −1) y (−1, 2, 1).

            Resolución explicada

            Coordenadas de v en B = solución de A·c = v con los vectores de B por columnas. Se factoriza A una vez:

            A = 121211112 = 10021011/311210−3−1004/3

            Para (1, 2, 3): L·y = (1, 2, 3) da y = (1, 0, 2) y U·c = y da c = (1/2, −1/2, 3/2). Igual con los demás (en el cuaderno quedan propuestos):

            vy (L·y = v)coordenadas (U·c = y)
            (1, 2, 3)(1, 0, 2)(1/2, −1/2, 3/2)
            (−2, 1, 3)(−2, 5, 10/3)(1/2, −5/2, 5/2)
            (4, −2, −1)(4, −10, −5/3)(−9/4, 15/4, −5/4)
            (−1, 2, 1)(−1, 4, 2/3)(3/2, −3/2, 1/2)

            Comprobación del segundo: ½(1, 2, 1) − 5/2(2, 1, 1) + 5/2(1, 1, 2) = (−2, 1, 3) ✓

            Ejercicio 1 (b)

            A = column_matrix(QQ, [(1, 2, 1), (2, 1, 1), (1, 1, 2)])
P, L, U = A.LU(pivot='nonzero')
for v in [(1, 2, 3), (-2, 1, 3), (4, -2, -1), (-1, 2, 1)]:
    y = resolucion_triangular(L, v, inferior=True)
    c = resolucion_triangular(U, y)
    print(v, "->", c, A * vector(c) == vector(v))

            Ejercicio 2

            Ejercicio 2 · Cuando la LU no basta

            Resolver cuatro sistemas con la LU y con solve_right: ¿qué se observa?

            Ejercicio 2 · sistemas no determinados

            Sistema 1: x + y + z=2x − y + z=42x + 2y + 2z=0 Sistema 2: x + y + z=2x − y + z=02x + 2y + 2z=4 Sistema 3: x + y + z=32x − y + z=1 Sistema 4: x + y=22x − y=13x + y=5

            Resolución explicada

            resolucion_triangular divide por la diagonal, así que sólo sirve si U es invertible (sistema compatible determinado y cuadrado). Y solve_right da una solución aunque haya infinitas, o un error si no hay ninguna. Hay que mirar la U:

            • Sistema 1: U = 1110−20000 e y = (2, 2, −4). La última ecuación de U·x = y es 0 = −4: incompatible. La sustitución da «división por cero» y solve_right dice «matrix equation has no solutions».
            • Sistema 2: misma U, y = (2, −2, 0): la última ecuación es 0 = 0. Compatible indeterminado: z = t, −2y = −2 ⇒ y = 1, x = 1 − t. solve_right devuelve sólo una solución, (1, 1, 0) (t = 0), sin avisar de que hay más.
            • Sistema 3 (2 ecuaciones, 3 incógnitas): U = 1110−3−1, y = (3, −5). Indeterminado: (4/3 − 2t/3, 5/3 − t/3, t). La sustitución triangular, que espera U cuadrada, devuelve (4/3, 5/3) sin z: no tiene sentido.
            • Sistema 4 (propuesto, 3 ecuaciones y 2 incógnitas): las dos primeras dan x = y = 1, y la tercera 3 + 1 = 4 ≠ 5: incompatible (la reducida de la ampliada tiene un pivote en la última columna).

            Ejercicio 4 · Una base de colores

            Los colores RGB son vectores de ℝ³: tres colores pueden ser una base y cualquier otro color, una combinación de ellos.

            Ejercicio 4 (a–d) · coordenadas de un color

            Elige tres colores (que no sean rojo, verde y azul). a) ¿Son base? b) Elige otro color y calcula sus coordenadas en esa base. c) Comprueba que es la mezcla de los de la base. d) ¿Tiene sentido cualquier combinación lineal?

            Resolución explicada

            Con los del cuaderno: verde lima (112, 251, 0), verde oliva (112, 151, 66) y violeta (106, 30, 118), y el color lila (207, 181, 230).

            Ejercicio 4

            A = column_matrix(QQ, [(112, 251, 0), (112, 151, 66), (106, 30, 118)])
print(A.rank(), A.det())                      # rango 3: son base
c = vector(QQ, (207, 181, 230))
x = A.solve_right(c)
show(x, x.n(digits=4))
print(x[0]*A.column(0) + x[1]*A.column(1) + x[2]*A.column(2) == c)
def muestra(rgb, x0):
    col = tuple(min(max(t / 255, 0), 1) for t in rgb)
    return polygon([(x0, 0), (x0 + 1, 0), (x0 + 1, 1), (x0, 1)], color=col, edgecolor='black')
show(sum(muestra(A.column(i), i) for i in range(3)) + muestra(c, 3.5), axes=False, aspect_ratio=1)

            a) rango 3 ⇒ base. b) Coordenadas (−377967/106318, 13625/1802, −242395/106318) ≈ (−3,56, 7,56, −2,28). c) La combinación reconstruye exactamente (207, 181, 230).

            d) No: matemáticamente cualquier combinación es un vector de ℝ³, pero un color RGB tiene cada componente entre 0 y 255, y como es mezcla aditiva de luz no existe «luz negativa». Las coordenadas negativas del lila significan que no se puede conseguir proyectando esas tres luces.

            Ejercicio 5 · filtros sobre imágenes

            Lee leon.jpg en escala de grises como una matriz y aplica el kernel K = −1−1−1−18−1−1−1−1: el nuevo valor de cada píxel es la suma de los productos elemento a elemento de K por el entorno 3 × 3 del píxel (convolución). Prueba otros kernels. ¿Cómo se pasa una imagen en negativo a normal?

            Resolución explicada

            Ejercicio 5

            import numpy as np
from PIL import Image
img = np.array(Image.open("leon.jpg").convert('L'), dtype=float)
print(img.shape)                        # (filas, columnas)
def aplicar_filtro(img, k):
    h, w = img.shape
    nueva = np.zeros((h - 2, w - 2))
    for i in range(h - 2):
        for j in range(w - 2):
            nueva[i, j] = np.sum(img[i:i+3, j:j+3] * k)
    return nueva
K = np.array([[-1, -1, -1], [-1, 8, -1], [-1, -1, -1]])
bordes = np.clip(aplicar_filtro(img, K), 0, 255)
show(graphics_array([matrix_plot(img, cmap='gray'), matrix_plot(bordes, cmap='gray')]), axes=False)

            Este kernel suma 0 (8 − 8·1): en zonas de color uniforme da 0 (negro) y sólo «se enciende» donde hay cambios bruscos: detecta bordes. Otros: 1/91/91/91/91/91/91/91/91/9 desenfoca (media), 0−10−15−10−10 enfoca. Para invertir un negativo basta 255 − valor en cada píxel (es su propio inverso).

            Ejercicio 6 · Cholesky

            Una matriz simétrica y definida positiva (xᵗAx > 0 para todo x ≠ 0) se factoriza como A = M·Mᵗ con M triangular inferior (Cholesky). Con cholesky(), factoriza las matrices de ejercicio6Cholesky.sobj.

            Resolución explicada

            Ejercicio 6

            A, B, C = load('ejercicio6Cholesky.sobj')
for X in (A, B, C):
    M = X.cholesky()
    print(X.nrows(), M.is_triangular("lower"), (M * M.transpose() - X).norm() < 1e-10)

            Cholesky es como una LU «simétrica» (U = Mᵗ): cuesta la mitad y es más estable. Siempre se puede aplicar a AᵗA si las columnas de A son independientes, que es justo la matriz de las ecuaciones normales de los mínimos cuadrados (práctica 6).

            Ejercicio 7 · el dron: 8000 sistemas por segundo

            Un dron de 6 motores calcula en cada instante la potencia x de cada motor resolviendo A·x = b, con A fija (geometría) y b, los datos de 6 sensores. A 8 kHz son 8000 sistemas por segundo. Factoriza A una vez y resuelve 8000 sistemas aleatorios con la LU: ¿cuánto se tarda?

            Resolución explicada

            Ejercicio 7 (necesita resolucion_triangular)

            A = matrix(RDF, [[5, 1, 1, 0, 0, 0], [1, 5, 1, 1, 0, 0], [1, 1, 5, 0, 1, 0],
                 [0, 1, 0, 5, 1, 1], [0, 0, 1, 1, 5, 1], [0, 0, 0, 1, 1, 5]])
P, L, U = A.LU()          # una sola vez, al arrancar
t = walltime()
for i in range(8000):
    b = vector(RDF, [random() for _ in range(6)])
    y = resolucion_triangular(L, P.transpose() * b, inferior=True)
    x = resolucion_triangular(U, y)
print("8000 sistemas en", walltime(t), "segundos")

            Con la LU calculada de antemano, cada sistema son dos sustituciones de 6 × 6: miles por segundo incluso en Python. (El cuaderno oficial hace sólo 100 iteraciones y no aplica P; con LU() sin opciones SageMath puede permutar filas, por eso aquí se multiplica b por Pᵗ.)
