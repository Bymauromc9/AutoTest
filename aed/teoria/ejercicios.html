            Abstracciones y especificaciones

            Especificaciones formales por el método axiomático (algebraico) y por el constructivo (operacional): escribir la sintaxis y la semántica de un TAD, evaluar expresiones aplicando los axiomas y razonar sobre constructores, completitud y precondiciones.

            Ejercicio 1.1 · Especificación axiomática del TAD Conjunto[T]

            Texto guía 2.1

            Desarrolla la especificación formal del TAD conjunto de tipo T (Nombre, Conjuntos, Sintaxis y Semántica) por el método axiomático. La especificación debe ser completa: todas las operaciones deben estar definidas en la semántica. Incluye Vacío, EsVacío, Inserta, Suprime, Miembro, Unión, Intersección, Diferencia y Cardinalidad.

            Resolución explicada

            Los constructores son Vacío e Inserta: cualquier conjunto es Inserta(x₁, Inserta(x₂, … Vacío)). Todas las demás operaciones llevan un axioma para Vacío y otro para Inserta.

            Especificación axiomática de Conjunto[T]

            NOMBRE
    Conjunto[T]
CONJUNTOS
    C     Conjunto de conjuntos de tipo T
    T     Conjunto de elementos (con una igualdad ==)
    B     Conjunto de booleanos {true, false}
    N     Conjunto de naturales
SINTAXIS
    Vacío:                      → C
    EsVacío:       C            → B
    Inserta:       T x C        → C
    Suprime:       T x C        → C
    Miembro:       T x C        → B
    Unión:         C x C        → C
    Intersección:  C x C        → C
    Diferencia:    C x C        → C
    Cardinalidad:  C            → N
SEMÁNTICA   ∀ x, y ∈ T; ∀ c, d ∈ C
     1. EsVacío (Vacío) = true
     2. EsVacío (Inserta (x, c)) = false
     3. Miembro (x, Vacío) = false
     4. Miembro (x, Inserta (y, c)) = SI x == y ⇒ true | Miembro (x, c)
     5. Suprime (x, Vacío) = Vacío
     6. Suprime (x, Inserta (y, c)) = SI x == y ⇒ Suprime (x, c) | Inserta (y, Suprime (x, c))
     7. Unión (Vacío, d) = d
     8. Unión (Inserta (x, c), d) = Inserta (x, Unión (c, d))
     9. Intersección (Vacío, d) = Vacío
    10. Intersección (Inserta (x, c), d) = SI Miembro (x, d) ⇒ Inserta (x, Intersección (c, d))
                                                         | Intersección (c, d)
    11. Diferencia (Vacío, d) = Vacío
    12. Diferencia (Inserta (x, c), d) = SI Miembro (x, d) ⇒ Diferencia (c, d)
                                                       | Inserta (x, Diferencia (c, d))
    13. Cardinalidad (Vacío) = cero
    14. Cardinalidad (Inserta (x, c)) = SI Miembro (x, c) ⇒ Cardinalidad (c)
                                                       | sucesor (Cardinalidad (c))

            Dos detalles que distinguen un conjunto de una lista: en el axioma 6, cuando se encuentra x se sigue suprimiendo en c (la expresión Inserta(3, Inserta(3, Vacío)) es legal y tiene el 3 «dos veces»), y en el 14 sólo se cuenta un elemento si no estaba ya. Si se quiere, se pueden añadir los dos axiomas que igualan expresiones de constructores: Inserta(x, Inserta(x, c)) = Inserta(x, c) (no hay repetidos) e Inserta(x, Inserta(y, c)) = Inserta(y, Inserta(x, c)) (no importa el orden); los demás axiomas ya funcionan sin ellos.

            Ejercicio 1.2 · Naturales: predecesor, producto y potencia

            Texto guía 2.3

            Partiendo de la especificación del TAD Natural vista en clase (cero, sucesor, suma, esCero, esIgual), añade las operaciones predecesor, producto y potencia. Ten en cuenta que hay casos en los que el resultado no es un número natural.

            Resolución explicada

            El predecesor de cero no es natural, y 0⁰ no está definido: añadimos un conjunto M de mensajes de error.

            Ampliación de Natural

            CONJUNTOS
    M     Conjunto de mensajes {"Error: cero no tiene predecesor", "Error: 0^0 no está definido"}
SINTAXIS
    predecesor:  N        → N ∪ M
    producto:    N x N    → N
    potencia:    N x N    → N ∪ M
SEMÁNTICA   ∀ m, n ∈ N
    8. predecesor (cero) = "Error: cero no tiene predecesor"
    9. predecesor (sucesor (n)) = n
   10. producto (cero, n) = cero
   11. producto (sucesor (m), n) = suma (n, producto (m, n))
   12. potencia (m, cero) = SI esCero (m) ⇒ "Error: 0^0 no está definido" | sucesor (cero)
   13. potencia (m, sucesor (n)) = SI esCero (m) ⇒ cero | producto (m, potencia (m, n))

            El producto usa (m + 1)·n = n + m·n y la potencia mⁿ⁺¹ = m·mⁿ. En el axioma 13 la condición evita que 0¹ = producto(0, potencia(0, 0)) arrastre el error de 0⁰.

            Ejercicio 1.3 · Evaluar dos expresiones con los naturales

            Texto guía 2.4

            Con la especificación anterior, calcula: (a) igual(predecesor(sucesor(cero)), sucesor(predecesor(cero))); (b) producto(sucesor(sucesor(cero)), sucesor(sucesor(cero))).

            Resolución explicada

            (a) Se evalúan los argumentos:

            1. predecesor(sucesor(cero)) = cero (axioma 9).
            2. predecesor(cero) = "Error: cero no tiene predecesor" (axioma 8), así que sucesor(predecesor(cero)) = sucesor(mensaje), que no es un natural: ningún axioma se puede aplicar.

            ResultadoError: el segundo argumento no es un natural, y el error se propaga a todo igual(…). Aunque «parece» que vale 1 = 0 + 1, con estos axiomas la expresión no tiene valor.

            (b) Con 2 = s(s(cero)):

            1. producto(s(s(cero)), 2) = suma(2, producto(s(cero), 2)) (axioma 11).
            2. producto(s(cero), 2) = suma(2, producto(cero, 2)) (11) = suma(2, cero) (10).
            3. suma(s(s(cero)), cero) = s(suma(s(cero), cero)) = s(s(suma(cero, cero))) = s(s(cero)) (axiomas 2 y 1 de la suma).
            4. suma(s(s(cero)), s(s(cero))) = s(s(suma(cero, s(s(cero))))) = s(s(s(s(cero)))).

            Resultadosucesor(sucesor(sucesor(sucesor(cero)))), es decir, 2 · 2 = 4.

            Ejercicio 1.4 · Evaluar expresiones de Pila[T]

            Evalúa con la especificación axiomática de Pila[T]: (a) tope(pop(push(a, push(b, push(b, crearPila))))); (b) esVacía(pop(push(a, pop(push(x, crearPila))))); (c) esVacía(push(4, pop(crearPila))).

            Resolución explicada

            Con los axiomas de clase: 1. esVacía(crearPila) = true, 2. esVacía(push(t, p)) = false, 3. pop(crearPila) = crearPila, 4. pop(push(t, p)) = p, 5. tope(crearPila) = error, 6. tope(push(t, p)) = t.

            1. (a) pop(push(a, push(b, push(b, crearPila)))) = push(b, push(b, crearPila)) (4); tope(push(b, …)) = b (6).
            2. (b) pop(push(x, crearPila)) = crearPila (4); pop(push(a, crearPila)) = crearPila (4); esVacía(crearPila) = true (1).
            3. (c) pop(crearPila) = crearPila (3); esVacía(push(4, crearPila)) = false (2).

            Ojo con (c): el resultado depende del axioma 3. Si la especificación dijera que pop(crearPila) es un error, el error se propagaría y la expresión no tendría valor.

            Ejercicio 1.5 · ¿Qué cambia si cambia la representación?

            Examen

            En una aplicación con conjuntos de palabras representados mediante listas, definimos la especificación formal axiomática del TAD Conjunto_palabras. ¿Qué partes de la especificación deben cambiar si en otra aplicación representamos los conjuntos con otra estructura?

            Resolución explicada

            Ninguna. La especificación dice qué hacen las operaciones, no cómo se implementan: el nombre, los conjuntos, la sintaxis y los axiomas de la semántica son los mismos se use una lista, una tabla de dispersión o un trie. Lo único que cambia es la implementación (el tipo de datos y el código de las operaciones). Si la especificación «hablara» de listas, estaría mal hecha: estaría mezclando la abstracción con la representación.

            Ejercicio 1.6 · Conjunto[Elemento] por el método constructivo

            Texto guía 2.6

            Propón un modelo subyacente adecuado para escribir la especificación constructiva del TAD Conjunto[Elemento] y escribe la semántica de las operaciones del ejercicio 4.

            Resolución explicada

            El «ejercicio 4» es la numeración del texto guía; aquí corresponde al 1.1 (Vacío, EsVacío, Inserta, Suprime, Miembro, Unión, Intersección, Diferencia y Cardinalidad). El modelo más natural son los conjuntos matemáticos, con ∅, ∪, ∩, −, ∈ y |·|. (Otra opción es Lista[T] sin repetidos, pero obliga a escribir cada postcondición con recorridos de la lista.)

            Semántica constructiva ∀ x ∈ E; c, d, r ∈ C; b ∈ B; n ∈ N

            pre-Vacío () ::= true                      post-Vacío (r) ::= r = ∅
pre-EsVacío (c) ::= true                   post-EsVacío (c; b) ::= b = (c = ∅)
pre-Inserta (x, c) ::= true                post-Inserta (x, c; r) ::= r = c ∪ {x}
pre-Suprime (x, c) ::= true                post-Suprime (x, c; r) ::= r = c − {x}
pre-Miembro (x, c) ::= true                post-Miembro (x, c; b) ::= b = (x ∈ c)
pre-Unión (c, d) ::= true                  post-Unión (c, d; r) ::= r = c ∪ d
pre-Intersección (c, d) ::= true           post-Intersección (c, d; r) ::= r = c ∩ d
pre-Diferencia (c, d) ::= true             post-Diferencia (c, d; r) ::= r = c − d
pre-Cardinalidad (c) ::= true              post-Cardinalidad (c; n) ::= n = |c|

            Todas las precondiciones son true: ninguna operación tiene casos de error. Si se añadieran Min o Max, su precondición sería c ≠ ∅.

            Ejercicio 1.7 · Ordena: semántica constructiva

            Examen

            En la especificación de Array(elemento) hay una operación Ordena: A → A que devuelve los elementos ordenados de mayor a menor. Escribe su semántica por el método constructivo, suponiendo que existen Tamaño: Array → Entero, ObtenValor: Array x Entero → Elemento, PonValor: Array x Entero x Elemento → Array y MayorQue: Elemento x Elemento → Booleano.

            Resolución explicada

            Suponemos posiciones de 1 a Tamaño(a). La postcondición tiene que decir dos cosas: que r está ordenado y que es una permutación de a (mismos elementos, el mismo número de veces). Sin la segunda, un array con todo ceros «cumpliría» la postcondición.

            Ordena por el método constructivo

            pre-Ordena (a) ::= true
post-Ordena (a; r) ::=
      Tamaño (r) = Tamaño (a)
    ∧ ∀ i ∈ [1, Tamaño (r) − 1]: NOT MayorQue (ObtenValor (r, i + 1), ObtenValor (r, i))
    ∧ ∀ e ∈ Elemento: |{ i ∈ [1, Tamaño (a)] | ObtenValor (a, i) = e }|
                      = |{ i ∈ [1, Tamaño (r)] | ObtenValor (r, i) = e }|

            La segunda línea dice que ningún elemento es mayor que el anterior (de mayor a menor, admitiendo repetidos); la tercera, que cada valor aparece las mismas veces en a y en r.

            Ejercicio 1.8 · Ordena: semántica axiomática

            Repite el ejercicio anterior con una especificación axiomática, suponiendo las operaciones que creas convenientes. ¿Cómo queda representado que el resultado es un array ordenado?

            Resolución explicada

            En el método axiomático no se puede «describir» el resultado: hay que decir cómo se obtiene a partir de otras operaciones. Usamos la idea de la ordenación por selección con dos auxiliares: PosMáximo(a, i), la posición del mayor elemento entre i y Tamaño(a), e Intercambia(a, i, j).

            Ordena por el método axiomático ∀ a ∈ A; i, j ∈ Z

            SINTAXIS
    Ordena:       A          → A
    OrdenaDesde:  A x Z      → A
    PosMáximo:    A x Z      → Z
    Intercambia:  A x Z x Z  → A
SEMÁNTICA
    Ordena (a) = OrdenaDesde (a, 1)
    OrdenaDesde (a, i) = SI i ≥ Tamaño (a) ⇒ a
                         | OrdenaDesde (Intercambia (a, i, PosMáximo (a, i)), i + 1)
    PosMáximo (a, i) = SI i ≥ Tamaño (a) ⇒ i
                       | SI MayorQue (ObtenValor (a, PosMáximo (a, i + 1)), ObtenValor (a, i))
                             ⇒ PosMáximo (a, i + 1) | i
    Intercambia (a, i, j) = PonValor (PonValor (a, i, ObtenValor (a, j)), j, ObtenValor (a, i))

            ¿Dónde está «ordenado»? En ninguna parte de forma explícita: en el método axiomático el significado es implícito, se deduce de los axiomas (en cada paso se pone en la posición i el mayor de lo que queda). En el constructivo, en cambio, la propiedad aparece explícitamente en la postcondición. Si se quiere dejar escrita, se puede añadir una consulta EstáOrdenado: A → B y demostrar, como propiedad del tipo, que EstáOrdenado(Ordena(a)) = true.

            Ejercicio 1.9 · Sintaxis de un grafo dirigido y etiquetado

            Examen · también es el 4.25

            Para la especificación del TAD grafo dirigido y etiquetado tenemos los conjuntos G (grafos), M (nodos), E (etiquetas), N (naturales), B (booleanos) y U (mensajes de error). Escribe la sintaxis de los constructores y de alguna operación de modificación y de consulta.

            Resolución explicada

            Sintaxis

            Constructores
    Crear:           → G                       grafo sin nodos
    InsertaNodo:     G x M        → G           añade un nodo aislado
    InsertaArista:   G x M x M x E → G          añade la arista <v, w> con etiqueta e
Modificación
    SuprimeArista:   G x M x M    → G
    SuprimeNodo:     G x M        → G           con todas sus aristas
    CambiaEtiqueta:  G x M x M x E → G ∪ U       error si la arista no existe
Consulta
    EsVacío:         G            → B
    ExisteArista:    G x M x M    → B
    Etiqueta:        G x M x M    → E ∪ U       error si la arista no existe
    GradoSalida:     G x M        → N
    NumNodos:        G            → N

            InsertaNodo hace falta como constructor porque, sólo con aristas, no se podrían construir grafos con nodos aislados. Si InsertaArista inserta también sus nodos cuando no existen, los tres constructores bastan para obtener cualquier grafo.

            Ejercicio 1.10 · Evaluar expresiones de Cola constructiva

            Texto guía 2.8

            Con la especificación constructiva de Cola(elemento), muestra los pasos para: (a) frente(inserta(4, inserta(5, crearCola))); (b) esVacíaCola(resto(inserta(a, crearCola))); (c) inserta(frente(crearCola), crearCola).

            Resolución explicada

            El modelo es Lista[T]: crearCola = crearLista, inserta(t, c) = concatenar(c, formarLista(t)), frente(c) = primero(c) con pre NOT esListaVacía(c), resto(c) = cola(c) con la misma precondición y esVacíaCola(c) = esListaVacía(c).

            1. (a) crearCola = [ ]; inserta(5, [ ]) = [5]; inserta(4, [5]) = concatenar([5], [4]) = [5, 4]. frente: la precondición NOT esListaVacía([5, 4]) se cumple; resultado primero([5, 4]) = 5 (el primero que entró).
            2. (b) inserta(a, [ ]) = [a]; resto([a]): pre ✓, cola([a]) = [ ]; esVacíaCola([ ]) = true.
            3. (c) frente(crearCola) = frente([ ]): la precondición NOT esListaVacía([ ]) es falsa. No se cumple el contrato, así que la especificación no dice nada: la expresión no está definida. Con una versión sin contratos, frente devolvería un mensaje de error, e inserta(mensaje, [ ]) tampoco tendría sentido.
            Ejercicio 1.11 · Si no se cumple la precondición

            ¿Qué ocurre en una especificación constructiva si en una expresión no se cumple la precondición? ¿Puede pasar algo parecido en una especificación algebraica?

            Resolución explicada

            Constructiva: la especificación es un contrato. Si el usuario no cumple la precondición, el implementador no tiene ninguna obligación: el resultado queda indefinido (puede devolver cualquier cosa, abortar con un assert…).

            Algebraica: no hay precondiciones, pero pasa algo parecido cuando para una expresión no hay ningún axioma aplicable (la especificación no es completa en ese caso): la expresión no se puede reducir a constructores y su valor no está definido. Por ejemplo, sin el axioma tope(pilaVacía) = …, Maude devuelve tope(pilaVacia) tal cual. La forma limpia de evitarlo es tratar el caso explícitamente con un conjunto de mensajes de error.

            Ejercicio 1.12 · ExisteArista en un grafo no dirigido

            Examen · también es el 4.27

            En la especificación algebraica de GrafoNoDirigido los constructores son GrafoVacío: → G e InsertaArista: G x N₁ x N₂ → G. Escribe la semántica de ExisteArista: G x N₁ x N₂ → B, que comprueba si la arista (N₁, N₂) está en el grafo.

            Resolución explicada

            Un axioma por constructor. Como el grafo es no dirigido, la arista (a, b) es la misma que (b, a):

            Semántica ∀ g ∈ G; a, b, n₁, n₂ ∈ N

            ExisteArista (GrafoVacío, n₁, n₂) = false
ExisteArista (InsertaArista (g, a, b), n₁, n₂) =
    SI (n₁ == a AND n₂ == b) OR (n₁ == b AND n₂ == a) ⇒ true
    | ExisteArista (g, n₁, n₂)
            Ejercicio 1.13 · Constructores y otros tipos de operaciones

            Examen

            En un TAD A definido con una especificación algebraica, ¿qué propiedad cumplen los constructores? ¿Qué otros tipos de operaciones puede haber?

            Resolución explicada

            Los constructores son el conjunto mínimo de operaciones con el que se puede obtener cualquier valor del tipo: toda expresión de tipo A se puede reducir, aplicando los axiomas, a una expresión que sólo contiene constructores. Por eso no tienen axiomas propios que los eliminen (como mucho, axiomas que igualan dos expresiones de constructores).

            Las demás son de modificación (devuelven un valor de A sin ser constructores, por ejemplo pop: P → P) y de consulta (devuelven un valor de otro tipo, por ejemplo tope: P → T o esVacía: P → B).

            Ejercicio 1.14 · esMenor en el TAD Entero

            Examen

            Con la especificación algebraica de Entero vista en clase (cero, sucesor, esCero, igual, suma), escribe la sintaxis y la semántica de esMenor, que dice si un entero es estrictamente menor que otro.

            Resolución explicada

            esMenor

            SINTAXIS
    esMenor: Z x Z → B
SEMÁNTICA   ∀ m, n ∈ Z
    esMenor (n, cero) = false
    esMenor (cero, sucesor (n)) = true
    esMenor (sucesor (m), sucesor (n)) = esMenor (m, n)

            Se «quita un sucesor» a cada lado hasta que uno de los dos llega a cero. Los tres axiomas cubren todas las combinaciones de constructores sin solaparse: el primero, cualquier n con cero; los otros dos, cero o sucesor contra sucesor.

            Ejercicio 1.15 · Demostración con el contador módulo 3

            Examen M01

            El TAD CMT (contador módulo 3) tiene Nuevo: → CMT, Inc: CMT → CMT y Dec: CMT → CMT, con los axiomas (∀ c): 1) Inc(Dec(c)) = c; 2) Dec(Inc(c)) = c; 3) Inc(Inc(Inc(c))) = c; 4) Dec(Dec(Dec(c))) = c. Demuestra, indicando los axiomas usados, que Dec(Nuevo) = Inc(Inc(Nuevo)).

            Resolución explicada
            1. Axioma 3 con c = Dec(Nuevo): Dec(Nuevo) = Inc(Inc(Inc(Dec(Nuevo)))).
            2. Axioma 1 con c = Nuevo: Inc(Dec(Nuevo)) = Nuevo, así que lo de dentro se simplifica: Inc(Inc(Inc(Dec(Nuevo)))) = Inc(Inc(Nuevo)).

            ResultadoDec(Nuevo) = Inc(Inc(Nuevo)), usando los axiomas 3 y 1. Tiene sentido: restar 1 módulo 3 es lo mismo que sumar 2.

            Ejercicio 1.16 · Corregir la semántica de un grafo de naturales

            Examen S01

            Dado este trozo de especificación (vacio: → G, esvacio: G → B, insertarnodo: G x N → G), corrige la SEMÁNTICA para que corresponda con el concepto usual de grafo (la especificación no es completa). Para las reglas eliminadas o modificadas, di en una línea por qué están mal.

            Semántica dada ∀ g ∈ G, ∀ n ∈ N

            1. esvacio (vacio) = true
2. esvacio (insertarnodo (vacio, n)) = false
3. esvacio (insertarnodo (g, n)) = esvacio (g)
4. insertarnodo (vacio, vacio) = vacio
5. insertarnodo (g, n) = insertarnodo (n, g)
            Resolución explicada
            • 1: correcta.
            • 2: correcta, pero es un caso particular; se generaliza a cualquier g.
            • 3: mal: un grafo al que se le añade un nodo nunca está vacío; además contradice a la 2 con g = vacio (daría true y false).
            • 4: mal: el segundo argumento de insertarnodo es un natural, no un grafo (no está bien tipada).
            • 5: mal: insertarnodo(n, g) tiene los argumentos al revés (tampoco está bien tipada).

            Semántica corregida ∀ g ∈ G; ∀ n, m ∈ N

            1. esvacio (vacio) = true
2. esvacio (insertarnodo (g, n)) = false
3. insertarnodo (insertarnodo (g, n), n) = insertarnodo (g, n)
4. insertarnodo (insertarnodo (g, n), m) = insertarnodo (insertarnodo (g, m), n)

            Las nuevas 3 y 4 recogen lo que seguramente se pretendía con las reglas 4 y 5: insertar un nodo que ya está no cambia el grafo, y el orden en que se insertan los nodos no importa.

            Ejercicio 1.17 · Máximo, mínimo, sucesor y predecesor en un conjunto

            Texto guía 2.2

            A la especificación del ejercicio 4 (aquí, el 1.1) añade máximo(C) y mínimo(C), y sucesor(C, n) y predecesor(C, n): el elemento de C más próximo a n por arriba y por abajo.

            Resolución explicada

            Hace falta una relación de orden «<» en T y mensajes de error (el conjunto vacío no tiene máximo; puede no haber ningún elemento mayor que n). Para sucesor y predecesor, la idea más limpia es filtrar: el sucesor de n es el mínimo de los mayores que n.

            Ampliación ∀ x, n ∈ T; ∀ c ∈ C

            CONJUNTOS
    M     Conjunto de mensajes {"Error: no existe"}
SINTAXIS
    máximo, mínimo:         C      → T ∪ M
    sucesor, predecesor:    C x T  → T ∪ M
    Mayores, Menores:       C x T  → C          (auxiliares)
SEMÁNTICA
    máximo (Vacío) = "Error: no existe"
    máximo (Inserta (x, c)) = SI EsVacío (c) ⇒ x
                              | SI máximo (c) < x ⇒ x | máximo (c)
    mínimo (Vacío) = "Error: no existe"
    mínimo (Inserta (x, c)) = SI EsVacío (c) ⇒ x
                              | SI x < mínimo (c) ⇒ x | mínimo (c)
    Mayores (Vacío, n) = Vacío
    Mayores (Inserta (x, c), n) = SI n < x ⇒ Inserta (x, Mayores (c, n)) | Mayores (c, n)
    Menores (Vacío, n) = Vacío
    Menores (Inserta (x, c), n) = SI x < n ⇒ Inserta (x, Menores (c, n)) | Menores (c, n)
    sucesor (c, n) = mínimo (Mayores (c, n))
    predecesor (c, n) = máximo (Menores (c, n))

            «Más próximo por arriba» se interpreta como estrictamente mayor (n no tiene por qué estar en C). El error de sucesor y predecesor sale solo: si no hay ninguno mayor (o menor), Mayores devuelve Vacío y mínimo(Vacío) es el mensaje.

            • (e) Es el árbol de Fibonacci: el peor AVL de altura n tiene un hijo peor caso de altura n − 1 y otro de altura n − 2 (con alturas desde 0 para un nodo solo).
            • (g) La nueva raíz es la raíz del hijo izquierdo, que a su vez se quita de su subárbol; si no hay hijo izquierdo, el resultado es el derecho.

            Todo está comprobado en Maude: por ejemplo, Nivel del árbol 1(2(4, 5), 3) en el nivel 1 da (2, 3) y peorAVL(3, t) tiene 7 nodos.

            Examen M05

            Escribe una especificación axiomática (nombre, conjuntos, sintaxis y semántica) de una tabla de dispersión abierta con pares (clave, valor) y las operaciones Crear (con un número de cubetas mayor que cero), Insertar, EsVacia, Tamaño (número de cubetas), Cuántos (número de elementos), Consulta (el valor asociado a una clave) y Suprimir (dada la clave).             Resolución explicada

            TablaDispersión[K, V]

            NOMBRE
    TablaDispersión[K, V]
CONJUNTOS
    T     Conjunto de tablas
    K     Conjunto de claves (con una igualdad ==)
    V     Conjunto de valores
    N     Conjunto de naturales
    B     Conjunto de booleanos
    U     Conjunto de mensajes {"Error: hace falta al menos una cubeta", "Error: la clave no está"}
SINTAXIS
    Crear:       N             → T ∪ U
    Insertar:    T x K x V     → T
    EsVacia:     T             → B
    Tamaño:      T             → N
    Está:        T x K         → B          (auxiliar)
    Cuántos:     T             → N
    Consulta:    T x K         → V ∪ U
    Suprimir:    T x K         → T
SEMÁNTICA   ∀ t ∈ T; ∀ k, j ∈ K; ∀ v ∈ V; ∀ n ∈ N
     1. Crear (cero) = "Error: hace falta al menos una cubeta"

     3. EsVacia (Insertar (t, k, v)) = false

            Resolución explicada

            Carro ∀ c ∈ C; ∀ p, q ∈ P; ∀ m, n ∈ N

            SINTAXIS
    carroVacío:              → C
    meter:       C x P x N   → C
    sacar:       C x P x N   → C
    cuántos:     C x P       → N
    precio:      C           → N          (el de un producto es precio: P → N)

    cuántos (carroVacío, p) = cero

            Examen

            Especifica por el método axiomático un grafo dirigido con nodos de tipo genérico T, usando Natural (cero, esCero, sucesor, suma, esIgual, resta) y Conjunto (vacío, esVacío, inserta, suprime, esMiembro, cardinalidad, unión…).             Resolución explicada

            GrafoDirigido[T]

            NOMBRE
    GrafoDirigido[T]
CONJUNTOS
    G     Conjunto de grafos dirigidos
    T     Conjunto de nodos (con una igualdad ==)
    C     Conjunto de conjuntos de nodos (Conjunto[T])
    N     Conjunto de naturales
    B     Conjunto de booleanos
SINTAXIS
    crear:                       → G
    insArista:     T x T x G     → G
    existeArista:  T x T x G     → B
    existeNodo:    T x G         → B
    gradoEntrada:  T x G         → N

    raíces:        G             → C

            Sí, con dispersión abierta (la cerrada no puede guardar más de M elementos).             Ejercicio 2.8 · Cubetas con listas ordenadas

            Las búsquedas sin éxito paran al encontrar un elemento mayor que el buscado: recorren, en promedio, la mitad de la cubeta en lugar de entera.             Dos palabras son anagramas si y sólo si tienen la misma firma: sus letras ordenadas (ROMA, AMOR, MORA y RAMO tienen la firma AMOR). El problema es un diccionario con clave la firma y valor la lista de palabras del grupo.

    T:= TablaAbierta(B)

            InsertaEnCubeta(T[h(f) mod B], nodo)
        finsi

    para cada cubeta de T, para cada nodo de la cubeta hacer
        si Longitud(nodo.palabras) ≥ 2 entonces Escribir(nodo.palabras)

            Ejercicio 5 · Memoria ocupada

            Estima la memoria de la tabla cerrada del ejercicio 3 y la que necesitaría con dispersión abierta. Los punteros ocupan 8 bytes y los enteros 4.

            Resolución explicada
            • Cerrada: B enteros, 20 · 4 = 80 bytes. Si cada celda necesita además un estado (vacía, ocupada, eliminada) que no se pueda codificar con un valor especial, por ejemplo 1 byte más: 100 bytes.
            • Abierta: B punteros + n nodos con (entero + puntero): 20 · 8 + 9 · (4 + 8) = 160 + 108 = 268 bytes. (Con la alineación de memoria cada nodo ocupa en la práctica 16 bytes: 160 + 144 = 304.)

            Es la fórmula general: cerrada k₂·B, abierta k₁·B + (k₁ + k₂)·n.

            Ejercicio 6 · ¿Cuándo para la búsqueda en dispersión abierta? (test)

            En dispersión abierta, la búsqueda de un elemento para cuando (señala todas las correctas): (a) se encuentra el elemento; (b) si la lista no está ordenada, cuando se encuentra un elemento distinto del buscado; (c) se llega a una cubeta vacía; (d) se llega al final de la lista; (e) se ha recorrido toda la tabla.

            Resolución explicada

            Resultado(a) y (d)

            Se busca sólo en la lista de la cubeta h(x): se para al encontrarlo o al acabar la lista. (b) es falsa: en una lista no ordenada hay que seguir; en una ordenada se pararía al encontrar uno mayor. (c) y (e) son criterios de la dispersión cerrada: en la abierta no se pasa de una cubeta a otra (una cubeta vacía no es más que una lista vacía, es decir, el caso (d)).

            Ejercicio 7 · ¿Con qué ocupación tardan lo mismo?

            Suponiendo que en dispersión abierta cada paso de la secuencia de búsqueda cuesta el doble que en la cerrada, ¿con qué porcentaje de llenado (n/B) tardan lo mismo?

            Resolución explicada

            Con x = n/B, la abierta tarda 2c·(1 + x) y la cerrada c·1/(1 − x):

            2(1 + x) = 1/(1 − x) ⇒ 2(1 − x²) = 1 ⇒ x² = 1/2 ⇒ x = √0,5 ≈ 0,707

            ResultadoCon un 70,7 % de ocupación. Por debajo es más rápida la cerrada; por encima, la abierta.

            Ejercicio 8 · Ordenar cuatro funciones de cadenas

            Ordena de peor a mejor (caso promedio) estas funciones para cadenas s: h₁(s) = longitud(s) mod B; h₂(s) = 375·longitud(s)³ mod B; h₃(s) = (Σ s[i−1]) mod B; h₄(s) = (Σ 31ⁱ·s[i−1]) mod B.

            Resolución explicada

            Resultadoh₂, h₁, h₃, h₄ (de peor a mejor)

            • h₂ y h₁ sólo dependen de la longitud: todas las palabras de igual longitud colisionan y sólo se usan tantas cubetas como longitudes distintas (unas pocas decenas). h₂ es aún peor: cualquier valor de h₂ sale de una longitud, así que no puede dar más valores distintos que h₁, y además longitudes distintas pueden coincidir (375 = 3·5³ comparte factores con muchos B).

            • h₄ (suma posicional con base 31) depende de cada carácter y de su posición: es la mejor.
            Ejercicio 9 · Redispersión doble para los DNI

            Guardamos los DNI (8 cifras) de los alumnos con dispersión cerrada, B = 1000 y h(x) = x mod 1000. Define una buena redispersión doble.

            Resolución explicada

            h usa las 3 últimas cifras; los sinónimos se distinguen en las 5 primeras, así que el salto C(x) tiene que depender de ellas. Además C(x) debe ser primo con 1000 = 2³·5³ (impar y no múltiplo de 5) para que la secuencia recorra toda la tabla:

            Redispersión doble

            hᵢ(x) = (h(x) + i·C(x)) mod 1000

operación C (x: entero): entero
    c:= 2·((x div 1000) mod 500) + 1         // impar, entre 1 y 999
    si c mod 5 == 0 entonces c:= c + 2         // ni múltiplo de 5
    devolver c                                 // primo con 1000

            Si se pudiera cambiar B, sería mejor un primo (p. ej. B = 1009) con C(x) = 1 + (x div 1000) mod 1008: cualquier salto entre 1 y 1008 recorre toda la tabla.

            Ejercicio 3.1 · ¿Por qué hace falta la marca $?

            Explica por qué en un trie hace falta una marca de fin de palabra $, en lugar de hacer corresponder las palabras con las hojas del árbol.

            Resolución explicada

            Porque una palabra puede ser prefijo de otra: si el conjunto tiene «sol» y «solar», la palabra «sol» acaba en un nodo interno (del que cuelga la a de «solar»), no en una hoja. Sin la marca no se podría distinguir «sol está en el conjunto» de «sol sólo es prefijo de solar». Con la marca, la palabra está si y sólo si el nodo al que se llega tiene un hijo $ (HayMarca).

            Ejercicio 3.2 · Añadir las vocales acentuadas

            Queremos representar palabras con tilde, así que se añaden al alfabeto {Á, á, É, é, Í, í, Ó, ó, Ú, ú}. ¿Cómo afecta a la memoria y al tiempo con nodos de arrays y de listas?

            Resolución explicada
            • Arrays: cada nodo tiene un puntero por carácter, así que crece en 10 punteros: la memoria (p + 1)·d·k₁ pasa de d a d + 10 (con d = 27, un 37 % más), aunque esos punteros casi siempre estén a NULO. El tiempo no cambia: O(m), un acceso directo por letra.
            • Listas: la memoria no cambia, (2p + 1)·(2k₁ + k₂): sólo se guardan los hijos que existen (si un carácter pasa a ocupar 2 bytes, crece k₂). El tiempo puede aumentar un poco, porque las listas de hijos de algunos nodos serán algo más largas, O(m·s) con s ligeramente mayor. Hay que definir el orden de los caracteres nuevos (por ejemplo, á justo después de a) para mantener las listas ordenadas.

            Ejercicio 3.4 · Operaciones de un nodo trie con listas

            Escribe Consulta, Inserta, PonMarca, QuitaMarca y HayMarca para nodos de trie representados como listas de celdas. Calcula la memoria y el tiempo de las operaciones.

            Resolución explicada

            Cada nodo es una lista ordenada con un nodo cabecera; la cabecera guarda la marca en su campo car ('$' o ' ') y cada celda siguiente, un hijo (carácter y puntero al nodo hijo).

            Nodo trie como lista ordenada de (carácter, hijo)

            tipo NodoTrie = registro
    car: carácter
    sig, ptr: Puntero[NodoTrie]
finregistro

operación Consulta (n: NodoTrie; c: carácter): Puntero[NodoTrie]
    tmp:= n.sig
    mientras tmp ≠ NULO AND tmp→car < c hacer
        tmp:= tmp→sig
    si tmp ≠ NULO AND tmp→car == c entonces devolver tmp→ptr
    sino devolver NULO

operación Inserta (var n: NodoTrie; c: carácter)       // en su sitio, si no estaba
    tmp:= PunteroA(n)
    mientras tmp→sig ≠ NULO AND tmp→sig→car < c hacer
        tmp:= tmp→sig
    si tmp→sig == NULO OR tmp→sig→car ≠ c entonces
        hijo:= NUEVO NodoTrie(' ', NULO, NULO)          // cabecera del nodo hijo, sin marca
        tmp→sig:= NUEVO NodoTrie(c, tmp→sig, hijo)

operación QuitaMarca (var n: NodoTrie)    n.car:= ' '
operación HayMarca (n: NodoTrie): booleano
    devolver n.car == '$'

            Memoria: cada celda tiene un carácter y dos punteros, 2k₁ + k₂. Hay una cabecera por nodo (p + 1, contando la raíz) y una celda por arista (p): unas (2p + 1)·(2k₁ + k₂) bytes. Tiempo: PonMarca, QuitaMarca y HayMarca son O(1); Consulta e Inserta recorren la lista de hijos, O(s) con s el número de hijos (como mucho d). Insertar o buscar una palabra de longitud m cuesta O(m·s).

            Ejercicio 3.5 · Tries para comprimir con COPIA(X, Y)

            Un compresor sustituye una secuencia larga que ya apareció antes por COPIA(X, Y): «X caracteres empezando por los que aparecieron Y posiciones antes». Así, «Modulador-Demodulador» queda «Modulador-DemCOPIA(8, 12)». Describe las características del trie en esta aplicación y cómo se usaría al comprimir.

            Resolución explicada
            • Qué guarda: las secuencias que empiezan en cada posición ya leída (sus prefijos hasta una longitud máxima L, por ejemplo 255), es decir, un trie de sufijos acotado. En cada nodo se guarda la última posición donde empezó esa secuencia.
            • Alfabeto: los 256 valores de un byte; los nodos con arrays gastarían demasiado, así que mejor listas (o una tabla de dispersión por nodo). No hace falta la marca $: cualquier prefijo es útil.
            • Tamaño: para que no crezca sin límite se acota la profundidad (L) y sólo se mantienen las posiciones de una ventana reciente.

            Compresión: en la posición i se baja por el trie con los caracteres siguientes mientras se pueda; se llega a la coincidencia más larga, de longitud X, que empezó en la posición j guardada en el nodo. Si X es suficientemente largo (que COPIA ocupe menos que los caracteres), se escribe COPIA(X, i − j) y se avanzan X posiciones; si no, se escribe el carácter. En ambos casos se insertan en el trie las secuencias que empiezan en las posiciones procesadas, actualizando la última posición de cada nodo. En el ejemplo, en la posición 13 (la o de «Demodulador», contando desde 0) se encuentra «odulador», que empezó en la 1: X = 8 e Y = 13 − 1 = 12.

            Ejercicio 3.6 · ¿Es un trie un TDA?

            Los tries se usan para representar conjuntos o diccionarios. ¿Es correcto definir un trie como un tipo abstracto de datos? Justifícalo con las propiedades de un TDA. Si lo es, ¿en qué modelo matemático se basa? Responde lo mismo para las tablas de dispersión y los árboles B.

            Resolución explicada

            No: un trie es una estructura de datos, una forma de representar el TDA Conjunto[cadena] o Diccionario[cadena, valor]. Un TDA se define por sus operaciones y su comportamiento, con independencia de la representación (encapsulamiento): al usuario le da igual que por dentro haya un trie, una tabla o una lista. El modelo matemático es el del TDA que implementa: los conjuntos (de secuencias de caracteres) o las funciones clave → valor en el caso del diccionario.

            Lo mismo pasa con las tablas de dispersión y los árboles B: son implementaciones de Conjunto o Diccionario (en el caso del árbol B, conjunto ordenado, con Min, Max y recorrido en orden). Matiz: en clase, el nodo de un trie sí se maneja como un TDA (un diccionario carácter → puntero, con Consulta, Inserta, PonMarca…), precisamente para poder cambiar su representación (arrays o listas) sin tocar las operaciones del trie.

            Ejercicio 3.8 · Claves de acceso por nombre y apellidos

            Un sistema multiusuario guarda para cada persona su nombre, sus apellidos y una clave de acceso; la operación básica es, dado el nombre y los apellidos, obtener la clave. Habrá muchísimos usuarios, muchos con nombres o apellidos comunes. ¿Cómo sería con tries? Ventajas, inconvenientes y otras estructuras adecuadas.

            Resolución explicada

            Un trie cuya clave es «nombre apellido1 apellido2» (con un separador), y la clave de acceso guardada en el nodo final, junto a la marca $. Una variante muy adecuada aquí: un trie cuyo «alfabeto» son palabras completas (como el ejemplo de las direcciones web de clase): el primer nivel son los nombres, el segundo los primeros apellidos y el tercero los segundos. Como hay muchos hijos por nodo, los nodos se representan con una tabla de dispersión o un árbol de búsqueda.

            • Ventajas: los nombres y apellidos comunes se guardan una sola vez (José, García, Martínez…), así que se ahorra memoria; el tiempo depende de la longitud del nombre, no del número de usuarios; permite listar en orden alfabético o buscar por prefijos (todos los «José García»).
            • Inconvenientes: más complejo de implementar; con nodos de arrays desperdicia mucha memoria; si apenas hubiera prefijos comunes, gasta más que otras estructuras por los punteros.
            • Alternativas: una tabla de dispersión con clave el nombre completo (O(1) en promedio, la más sencilla) o, si los datos están en disco, un árbol B.

            Ejercicio 3.10 · Otras representaciones de los nodos de un trie

            Un nodo de trie es una asociación de caracteres a punteros. ¿Qué otras estructuras se podrían usar para evitar el desperdicio de memoria de los arrays y las búsquedas lentas de las listas? Justifícalo y da la eficiencia de Miembro en el trie.

            Resolución explicada
            • Una tabla de dispersión por nodo (carácter → puntero), pequeña y con B acorde al número de hijos: acceso O(1) en promedio y memoria proporcional a los hijos que hay. Miembro: O(m) en promedio.

            Define el TDA Relación de equivalencia de un tipo genérico con algún método formal. Añade operaciones para quitar un elemento de su clase y ponerlo en una clase nueva o en otra clase. Implementa esas operaciones con la representación de clase.

            Por el método constructivo, con modelo una partición P del conjunto C (conjunto de subconjuntos disjuntos no vacíos que lo cubren); clase(P, x) es el bloque de P que contiene a x.

            RelEquiv[T] ∀ P, Q ∈ R; ∀ x, y ∈ T

            pre-Crear (C) ::= true
post-Crear (C; P) ::= P = { {x} | x ∈ C }
pre-Unión (P, x, y) ::= x ∈ ∪P ∧ y ∈ ∪P
post-Unión (P, x, y; Q) ::= Q = (P − {clase(P, x), clase(P, y)}) ∪ {clase(P, x) ∪ clase(P, y)}
pre-Equivalentes (P, x, y) ::= x ∈ ∪P ∧ y ∈ ∪P
post-Equivalentes (P, x, y; b) ::= b = (clase(P, x) = clase(P, y))
pre-Separa (P, x) ::= x ∈ ∪P
post-Separa (P, x; Q) ::= Q = (P − {clase(P, x)}) ∪ {{x}} ∪ ({clase(P, x) − {x}} − {∅})
pre-Mueve (P, x, y) ::= x ∈ ∪P ∧ y ∈ ∪P
post-Mueve (P, x, y; Q) ::= SI clase(P, x) = clase(P, y) ⇒ Q = P
                           | Q = Unión (Separa (P, x), x, y)

            (En lugar de Encuentra, que devuelve un representante arbitrario, se especifica Equivalentes, que es lo que de verdad se observa.) La implementación con punteros al padre tiene un problema: si x tiene hijos (elementos que apuntan a x), al quitarlo se quedarían colgando de él. Hay que reengancharlos al padre de x, o, si x es la raíz, elegir uno de ellos como nueva raíz:

            Separa y Mueve con punteros al padre (R[raíz] = −altura)

            operación Separa (var R: RelEquiv[N]; x: entero)
    si R[x] > 0 entonces                         // x no es raíz: sus hijos suben a su padre
        para i:= 1, ..., N hacer
            si R[i] == x entonces R[i]:= R[x]
    sino                                         // x es raíz: el primer hijo es la nueva raíz
        nueva:= 0
        para i:= 1, ..., N hacer
            si R[i] == x entonces
                si nueva == 0 entonces nueva:= i; R[i]:= R[x]     // hereda la altura (cota)
                sino R[i]:= nueva
            finsi
    finsi
    R[x]:= 0                                     // x queda solo en una clase nueva

operación Mueve (var R: RelEquiv[N]; x, y: entero)
    si Encuentra(R, x) ≠ Encuentra(R, y) entonces
        Separa(R, x)
        Unión(R, x, Encuentra(R, y))             // x es ahora una raíz de altura 0

            Separa cuesta O(N) (hay que encontrar a los hijos de x, porque los punteros sólo van hacia el padre); Mueve, lo mismo. Las alturas guardadas siguen siendo cotas superiores, que es lo único que necesita el balanceo.

            La forma eficiente: (1) volcar los dos árboles a listas ordenadas con un recorrido en inorden, O(n + m); (2) mezclarlas como con listas ordenadas, O(n + m); (3) construir el AVL resultado a partir de la lista ordenada tomando el elemento central como raíz, O(n + m), y queda perfectamente balanceado.

            Operaciones de conjuntos con AVL

            operación Unión (A, B: ArbolAVL; var C: ArbolAVL)
    LA:= Inorden(A)                       // lista ordenada
    LB:= Inorden(B)
    LC:= UniónListasOrdenadas(LA, LB)     // la mezcla del tema 2 (o Intersección, Diferencia)
    V:= ListaAArray(LC)
    C:= Construye(V, 1, Longitud(LC))

operación Construye (V: array; ini, fin: entero): ArbolAVL
    si ini > fin entonces devolver NULO
    med:= (ini + fin) div 2
    A:= NUEVO NodoAVL(V[med])
    A→izq:= Construye(V, ini, med − 1)
    A→der:= Construye(V, med + 1, fin)
    A→altura:= 1 + max(Altura(A→izq), Altura(A→der))
    devolver A

            Total O(n + m). La alternativa directa, insertar en una copia de A cada elemento de B (o buscar cada elemento de A en B), cuesta O(m·log(n + m)), mejor sólo si un conjunto es mucho más pequeño que el otro. Comparación: con listas ordenadas también es O(n + m); con arrays de booleanos, O(R); con tablas de dispersión, O(n + m) pero el resultado no está ordenado. La ventaja del AVL es que además Miembro, Inserta y Suprime son O(log n).

            Al insertar en un AVL, como mucho se hace un rebalanceo. Modifica la inserción para que no se compruebe la condición de equilibrio después de haber reestructurado. ¿Qué mejora se obtiene?

            Resolución explicada

            Se añade un parámetro de salida crece: «el subárbol ha aumentado de altura». Tras una rotación el subárbol recupera su altura anterior, así que crece = FALSE y los antecesores ya no hacen nada; lo mismo si un nodo queda con los dos lados iguales.

            Inserta con el indicador «crece»

            operación Inserta (var A: Puntero[NodoAVL]; x: T; var crece: booleano)
    si A == NULO entonces
        A:= NUEVO NodoAVL(x); A→altura:= 0
        crece:= TRUE
    sino si x < A→clave entonces
        Inserta(A→izq, x, crece)
        si crece entonces
            si Altura(A→izq) − Altura(A→der) > 1 entonces
                si x < A→izq→clave entonces RSI(A) sino RDI(A)
                crece:= FALSE                    // recupera la altura: nada más arriba

                A→altura:= 1 + max(Altura(A→izq), Altura(A→der))
                crece:= (Altura(A→izq) > Altura(A→der))   // si quedan iguales, no ha crecido
            finsi
        finsi
    sino si x > A→clave entonces                 // simétrico, con RSD y RDD
        ...
    sino crece:= FALSE                           // ya estaba

            La mejora es de constante: el orden sigue siendo O(log n) (hay que bajar hasta la hoja), pero a la vuelta de la recursividad, a partir del primer nodo que no crece, no se calculan alturas ni se comprueba la condición. En promedio se ahorra la mayor parte del trabajo de subida.

            Propón una representación para un árbol B de orden p con enteros. Escribe Miembro(elemento, árbol_B) e Inserta(elemento, árbol_B). ¿Qué hay que tener en cuenta si los nodos están en disco?

            Resolución explicada

            Tipo, Miembro e Inserta

            tipo ArbolB = Puntero[NodoB]
tipo NodoB = registro
    n: entero                                   // número de claves (≤ p − 1)
    clave: array [1..p] de entero               // una de sobra para partir con comodidad
    hijo: array [0..p] de Puntero[NodoB]        // todos NULO en las hojas
finregistro

operación Miembro (x: entero; A: ArbolB): booleano
    si A == NULO entonces devolver FALSE
    i:= 1
    mientras i ≤ A→n AND A→clave[i] < x hacer i:= i + 1
    si i ≤ A→n AND A→clave[i] == x entonces devolver TRUE
    devolver Miembro(x, A→hijo[i − 1])          // la rama entre clave[i−1] y clave[i]

operación Inserta (x: entero; var A: ArbolB)
    si A == NULO entonces A:= NodoCon(x, NULO, NULO); acabar
    InsertaRec(x, A, sube, med, nuevo)
    si sube entonces A:= NodoCon(med, A, nuevo)          // se partió la raíz: crece la altura

operación InsertaRec (x: entero; A: ArbolB; var sube: booleano; var med: entero; var nuevo: ArbolB)
    i:= posición de la primera clave ≥ x en A (como en Miembro)
    si i ≤ A→n AND A→clave[i] == x entonces sube:= FALSE; acabar      // ya estaba
    si A→hijo[0] == NULO entonces                                       // hoja
        sube:= TRUE; med:= x; nuevo:= NULO
    sino
        InsertaRec(x, A→hijo[i − 1], sube, med, nuevo)
    finsi
    si sube entonces                       // hay que meter (med, nuevo) en A, en la posición i
        desplazar clave[i..n] y hijo[i..n] una posición a la derecha
        A→clave[i]:= med; A→hijo[i]:= nuevo; A→n:= A→n + 1
        si A→n ≤ p − 1 entonces sube:= FALSE
        sino                                                            // partir A
            k:= ⌈(p − 1)/2⌉ + 1                                         // posición de la mediana
            med:= A→clave[k]
            nuevo:= nodo con clave[k+1..p] e hijo[k..p] de A
            A→n:= k − 1                                                 // sube = TRUE
        finsi
    finsi

            En disco: lo que cuesta es el número de accesos a bloques, no las comparaciones. Cada nodo ocupa un bloque (se elige p para que quepa justo), los punteros son números de bloque, la raíz se mantiene en memoria y cada nodo visitado es una lectura (la búsqueda dentro del nodo es en memoria y puede ser binaria). Al modificar un nodo hay que escribirlo de vuelta, y al partir se escriben dos o tres bloques. Con p grande, la altura (logp/2 n) es muy pequeña: 3 o 4 lecturas para millones de claves.

            Escribe en pseudocódigo la eliminación de un elemento en un árbol B, tratando todos los casos en nodo hoja o interno.

            Resolución explicada

            Eliminación en un árbol B de orden p (d = ⌊(p − 1)/2⌋)

            operación Elimina (x: entero; var A: ArbolB)
    EliminaRec(x, A)
    si A→n == 0 AND A→hijo[0] ≠ NULO entonces       // la raíz se quedó sin claves
        A:= A→hijo[0]                               // el árbol baja un nivel

operación EliminaRec (x: entero; A: ArbolB)
    i:= posición de la primera clave ≥ x en A
    si i ≤ A→n AND A→clave[i] == x entonces
        si A→hijo[0] == NULO entonces               // en una hoja: se quita
            quitar clave[i] de A
        sino                                        // en un nodo interno
            y:= Máximo(A→hijo[i − 1])               // la anterior: la mayor de la rama izquierda
            A→clave[i]:= y
            EliminaRec(y, A→hijo[i − 1])
            Arregla(A, i − 1)
        finsi
    sino si A→hijo[0] ≠ NULO entonces               // bajar por la rama correspondiente
        EliminaRec(x, A→hijo[i − 1])
        Arregla(A, i − 1)
    finsi                                           // si es hoja y no está, no hay nada que hacer

operación Arregla (A: ArbolB; j: entero)           // el hijo j de A puede tener d − 1 claves
    H:= A→hijo[j]
    si H→n ≥ d entonces acabar
    si j > 0 AND A→hijo[j − 1]→n > d entonces      // préstamo del hermano izquierdo
        meter A→clave[j] al principio de H (con el último hijo del hermano)
        A→clave[j]:= última clave del hermano izquierdo (se quita de él)
    sino si j < A→n AND A→hijo[j + 1]→n > d entonces   // préstamo del hermano derecho
        meter A→clave[j + 1] al final de H (con el primer hijo del hermano)
        A→clave[j + 1]:= primera clave del hermano derecho (se quita de él)
    sino si j < A→n entonces                        // fusión con el derecho
        H:= H + A→clave[j + 1] + hermano derecho; quitar clave[j + 1] e hijo[j + 1] de A
    sino                                            // fusión con el izquierdo
        hermano izquierdo:= hermano + A→clave[j] + H; quitar clave[j] e hijo[j] de A
    finsi
    // si A se ha quedado por debajo del mínimo, lo arregla su padre al volver de la recursividad

            Todos los casos: hoja con más de d claves (se quita y ya está), hoja con d (préstamo de un hermano o fusión), nodo interno (sustituir por la anterior y eliminarla de su hoja), fusión que deja al padre por debajo del mínimo (se repite hacia arriba) y raíz vacía (desaparece). Coste O(p·logp/2 n).

    finpara

            Diseña un algoritmo que cuente los ciclos simples de un grafo no dirigido. ¿Cuál es su orden? ¿Cuántos ciclos puede haber como máximo?

            Resolución explicada

            Con backtracking: para cada nodo s (de menor a mayor) se buscan todos los caminos simples que empiezan en s y sólo pasan por nodos mayores que s; cada vez que desde el último nodo hay una arista de vuelta a s y el camino tiene al menos 3 nodos, se ha cerrado un ciclo. Así cada ciclo se cuenta sólo desde su nodo menor, pero dos veces (una por sentido), de modo que al final se divide entre 2.

            Contar ciclos simples

            operación ContarCiclos (G): entero
    total:= 0
    para s:= 1, ..., n hacer
        enCamino[*]:= FALSE
        Extender(s, s, 1, total)
    devolver total div 2

    enCamino[v]:= TRUE
    para cada w adyacente a v hacer
        si w == s AND long ≥ 3 entonces total:= total + 1
        sino si w > s AND NOT enCamino[w] entonces Extender(s, w, long + 1, total)
    finpara
    enCamino[v]:= FALSE                    // deshacer: v puede estar en otros caminos

            El coste es proporcional al número de caminos simples, que puede ser exponencial (del orden de n! en un grafo completo): no se conoce nada polinómico, porque puede haber exponencialmente muchos ciclos.             Ejercicio 4.22 · El grafo reducido es siempre un GDA

            Demuestra que el grafo reducido de un grafo dirigido G cualquiera (un nodo por componente fuertemente conexo) es siempre un GDA.

            Resolución explicada

            Por reducción al absurdo. Supongamos que el grafo reducido tiene un ciclo C₁ → C₂ → … → Cₖ → C₁ con k ≥ 2 componentes distintos (no hay lazos: las aristas dentro de un componente no se representan). Sean x ∈ C₁ e y ∈ C₂. Hay un camino de x a y: dentro de C₁ hasta el origen de la arista C₁ → C₂ y luego dentro de C₂ hasta y (cada componente es fuertemente conexo). Y hay un camino de y a x siguiendo el resto del ciclo C₂ → … → Cₖ → C₁ de la misma forma. Entonces x e y son mutuamente alcanzables y estarían en el mismo componente fuertemente conexo, en contra de que C₁ ≠ C₂. Luego el grafo reducido no tiene ciclos. ∎

            Ejercicio 4.23 · ¿Es bipartido?

            Un grafo no dirigido es bipartido si V se puede partir en V₁ y V₂ de forma que toda arista tenga un extremo en cada parte. Da un algoritmo O(n + a) que lo compruebe (pista: una BPP que asigne la parte 1 o 2 a cada nodo).

            Resolución explicada

            Se «colorea» con una BPP: el primer nodo de cada componente va a la parte 1 y cada hijo, a la parte contraria de su padre. Si una arista une dos nodos de la misma parte, no es bipartido (hay un ciclo de longitud impar).

            Comprobar si un grafo es bipartido

            var parte: array [1..n] de entero         // 0 = no visitado; 1 o 2

operación EsBipartido: booleano
    para v:= 1, ..., n hacer parte[v]:= 0
    para v:= 1, ..., n hacer
        si parte[v] == 0 entonces
            si NOT Colorea(v, 1) entonces devolver FALSE
    devolver TRUE

operación Colorea (v: nodo; p: entero): booleano
    parte[v]:= p
    para cada w adyacente a v hacer
        si parte[w] == 0 entonces
            si NOT Colorea(w, 3 − p) entonces devolver FALSE
        sino si parte[w] == p entonces
            devolver FALSE                     // dos vecinos en la misma parte
    finpara
    devolver TRUE

            Es una BPP: O(n + a) con listas de adyacencia (O(n²) con matrices). Al terminar, parte[] da la partición V₁, V₂.

    si cuántos == 1 entonces devolver r sino devolver 0

            O(n + a). Si no se quiere usar el razonamiento anterior (o el grafo pudiera tener ciclos), se comprueba con una BPP desde r que se visitan los n nodos, también O(n + a).

            (a) Con «Dijkstra de máximos», al principio D[X] = 5 y D[Y] = 1; se escoge el mayor, X, y se da por definitivo. Pero el camino más largo hasta X es I → Y → X, de longitud 11, que pasa por un candidato con D más pequeño. La idea de Dijkstra («el escogido ya no puede mejorar») sólo vale porque al alargar un camino el coste nunca baja; buscando máximos, un camino que ahora es corto puede crecer y superar al escogido.

            (b) En un GDA basta procesar los nodos en orden topológico (como en el 4.26) quedándose con el máximo:

            Camino más largo en un GDA (camino crítico)

            ordenar topológicamente los nodos                 // O(n + a)
L[*]:= −∞; L[Inicio]:= 0
para cada v en orden topológico hacer
    para cada w adyacente a v hacer
        si L[v] + C[v, w] > L[w] entonces
            L[w]:= L[v] + C[v, w]
            P[w]:= v                              // para recuperar el camino crítico
devolver L[Final]

            Cuando le toca a v, todos sus predecesores ya están procesados, así que L[v] ya es el máximo. Cuesta O(n + a) con listas (O(n²) con matrices). Es el cálculo del camino crítico de los métodos de planificación (PERT/CPM).

            Ejercicio 4.35 · El orden posterior da un orden topológico

            En un GDA, numeramos los nodos con un contador que empieza en N y baja en 1 cada vez que termina una llamada de bpp. Demuestra que el resultado es un orden topológico.

            Resolución explicada

            Hay que ver que para toda arista ⟨v, w⟩ la llamada de w termina antes que la de v (así w recibe un número mayor). Cuando bpp(v) examina la arista, w puede estar:

            • No visitado: se llama a bpp(w) desde bpp(v), y una llamada interna termina antes que la que la contiene.
            • Visitado y terminado: su llamada ya ha terminado y la de v sigue en curso, así que v terminará después.
            • Visitado y en curso: entonces w es un antecesor de v en la pila de llamadas, hay un camino w ⇝ v y, con la arista ⟨v, w⟩, un ciclo. Imposible en un GDA.

            En los dos casos posibles, w termina antes que v, recibe un número mayor y por tanto num[v] < num[w] para toda arista: es una numeración topológica. ∎

    esPA: array [1..n] de booleano
    cont: entero

operación bppPA (v: nodo)
    cont:= cont + 1
    nbpp[v]:= cont; bajo[v]:= nbpp[v]
    hijos:= 0
    para cada w adyacente a v hacer
        si nbpp[w] == 0 entonces                   // arista del árbol
            padre[w]:= v; hijos:= hijos + 1
            bppPA(w)
            bajo[v]:= min(bajo[v], bajo[w])
            si padre[v] ≠ 0 AND bajo[w] ≥ nbpp[v] entonces esPA[v]:= TRUE
        sino si w ≠ padre[v] entonces              // arco de retroceso
            bajo[v]:= min(bajo[v], nbpp[w])
        finsi
    finpara
    si padre[v] == 0 AND hijos ≥ 2 entonces esPA[v]:= TRUE    // la raíz

operación PuntosArticulación
    cont:= 0; nbpp[*]:= 0; esPA[*]:= FALSE
    para v:= 1, ..., n hacer
        si nbpp[v] == 0 entonces padre[v]:= 0; bppPA(v)

            Es una BPP con trabajo O(1) extra por arista: O(n + a) con listas y O(n²) con matrices.

            Ejercicio 4.40 · Las hojas nunca son puntos de articulación

            Demuestra, sin usar las propiedades del algoritmo, que las hojas del árbol de expansión en profundidad nunca son puntos de articulación.

            Resolución explicada

            Sea T el árbol de expansión (en profundidad, aunque vale para cualquiera) del componente conexo que contiene a v, y v una hoja de T. Si se quita una hoja de un árbol, lo que queda, T − v, sigue siendo un árbol, luego conexo, y contiene a todos los nodos del componente salvo v. Como T − v es un subgrafo de G − v, todos esos nodos siguen conectados en G − v: quitar v no divide el componente, así que v no es un punto de articulación. ∎

            Ejercicio 4.46 · Floyd o n veces Dijkstra

            Para los caminos mínimos entre todos los pares se puede usar Floyd o Dijkstra n veces. ¿Cuándo es más rápida cada opción en órdenes de complejidad (con las implementaciones de clase)?

            Resolución explicada
            • Floyd: O(n³), con matrices o con listas.
            • Dijkstra n veces: con matrices, n · O(n²) = O(n³), el mismo orden (y Floyd es más sencillo y tiene una constante menor). Con listas y un montículo, n · O(a log n) = O(n·a·log n).

            Por tanto, con grafos escasos (a ≪ n²/log n) es más rápido Dijkstra n veces con montículo; con grafos densos (a ≈ n²) es mejor Floyd: O(n³) frente a O(n³ log n).

            Ejercicio 4.50 · Conectividad k y grados mayores o iguales que k

            Demuestra que es cierta o da un contraejemplo: «Dado un grafo no dirigido G cualquiera, la conectividad de G es k ⇔ todos los vértices de G tienen grado k o mayor».

            Resolución explicada

            Es falsa. La implicación «⇒» sí es cierta: si algún vértice v tuviera grado g < k, quitando sus g vecinos (menos de k nodos) v quedaría aislado y el grafo se desconectaría, en contra de que la conectividad sea k (en un grafo completo Kₙ la conectividad es n − 1 y todos los grados son n − 1, así que también se cumple). Pero «⇐» falla: en la «pajarita» de la figura (dos triángulos que comparten el vértice c) todos los grados son 2 o más, pero quitando sólo c el grafo se parte en dos: su conectividad es 1, no 2. La condición sobre los grados es necesaria, pero no suficiente.
